# Fingerprints of the Apple marks found in the pinned upstream themes (ADR-0017, owner decision 2026-10-23): the Apple
# logo glyph and the Finder face. Input of packaging/arch/icons-compose.py (default next to it; --signatures FILE
# overrides). The composer fails when the composed theme draws or embeds one of them, so a mark that a pin change, an
# alias or a copy under another name brings back cannot ship. It also fails on a byte-for-byte copy of a file listed in
# icons-apple-logos.txt.
# Two kinds of lines:
#   <sha256>         a path signature: the `d` data with runs of white space collapsed to one space, trimmed, and the
#                    first moveto (`M x y` / `m x y`) removed, so the same glyph placed elsewhere matches;
#   raster:<sha256>  the bytes of a raster: a PNG file of the theme, or an image embedded in an SVG as a base64 data
#                    URI (hidden ones too, display none), decoded with white space and missing padding tolerated.
# Only hashes are stored here: the repository holds no Apple artwork.
# Source: every path of the files in icons-apple-logos.txt was drawn alone and looked at; the 23 that draw the apple
# (alone, on an iMac chin, a mouse, an iPod, a drive, a menu bar, the rainbow logo pieces) and the 3 that draw the
# Finder face (its profile half, the nose line, the symbolic nose) are below, then the raster of the Apple logo hidden
# in Pebble's preferences-tweaks-slingshot.svg (reviewer finding 2026-10-23).
