# dock spec · shell-engineer · M1

## macOS reference behavior (from design/reference/, described in words — no Apple images committed)
Measured in F1 (docs/testing/f1-reference-gaps.md, Dock): a floating rounded-rectangle glass shelf (radius about 24, not a capsule) about 6 pt above the bottom edge, a little lighter than its backdrop with a visible light rim along the top edge, strongly translucent over the wallpaper; icon body about 0.735 of the pitch; a small dark dot under running apps; a hairline separator before the folders and the Trash; a label capsule with a downward tail above the hovered icon; an icon menu (rounded panel with a tail) above the icon. Icons magnify only when the option is on (off by default).

## Look (fidelity pass, 2026-10-19)
The shelf is `Material` with the Dock overrides: tint alpha `dock.tintAlphaDark` 0.52 / `dock.tintAlphaLight` 0.42 per appearance (not the A2 text clamp: the shelf holds icons only, the labels are separate capsules on the global material), highlight `dock.highlightOpacity` (0.34) and a white 1 px rim `dock.rimOpacity` (0.34), always over a real compositor blur region (`BackgroundEffect.blurRegion`, nothing faked). Reduce Transparency still makes the shelf opaque (the override applies only while the material is not opaque). Radius `radius.dock` 24, padding `dock.padding` 10, separator `dock.separatorHeight` 49, spacing 4. The Trash uses the icon theme (`user-trash` empty, `user-trash-full`) in the user's icon mode (`TintedIcon`, ADR-0014); without those theme icons it falls back to the symbolic glyph on a rounded tile. The menu tail is `dock.menuTailWidth/Height/Gap` (19 / 13 / 16).

## Purpose and non-goals
Pinned, running and recent apps, Trash, launch/focus/cycle, launch bounce, badges, drag to reorder/remove, file drops, magnification, autohide, item context menu. Non-goals now: folders/stacks, left/right Dock position, per-monitor differences.

## Functional requirements
1. One layer-shell window per screen, namespace `grassfield-dock`, anchored bottom+left+right (full width, transparent), exclusive zone = shelf height + bottom margin (0 with autohide). Input is restricted with a mask to the shelf (plus the magnified area while hovered), or to a 2 px bottom strip while hidden.
2. Items (`DockModel.js`, pure): pinned desktop entry ids in the user's order (unresolvable ids skipped, duplicates merged), then running apps that are not pinned (foreign-toplevel app id mapped to an entry; case-insensitive), a separator, the Trash. Windows are never matched by title.
3. Running indicator dot under apps with at least one window: it follows the appearance (macOS: pure white in dark mode, pure black in light mode, `colors.indicator`), and the shelf tint alpha is chosen per appearance (`dock.tintAlphaDark` 0.52, `dock.tintAlphaLight` 0.42) so that the dot keeps 3:1 or more against the shelf over ANY backdrop, wallpaper or window (black, white, greys, noise: autohide and floating windows put a window under the shelf): worst case 3.4:1 in dark (white backdrop), 3.7:1 in light (black backdrop), computed by tests/unit/tst_bartone.qml with `BarToneLogic.shelfLuminance` and measured by tests/visual/contrast.sh `dock`. No wallpaper sampling is needed.
4. Click, Return, Space: not running → `DesktopEntry.execute()`; running and not focused → activate the most recently focused window of the app (and move it back from `special:hidden`); running and already focused → cycle to the app's next window. Trash → `gio open trash:///`.
5. Tooltip with the app name above the icon (hover or keyboard focus), via the `Tooltip` component. The label appears after `dock.tooltipDelay` (250 ms) on an icon (at once for keyboard focus and the drag Remove capsule, and for the next icon within `dock.tooltipWarm` (400 ms) of a label), and an icon keeps its hovered state `dock.hoverHold` (80 ms) after the pointer leaves it, so crossing the gap between two icons does not flicker.
6. Magnification (`Magnify.js`, pure): falloff = quintic smootherstep, scale(d) = 1 + (max-1)·(1 - S(d/R)), S(t) = 10t³ - 15t⁴ + 6t⁵, for pointer distance d < R, R = `dock.magnificationRadius` (3) icon pitches; max = `dock.magnification` (default 1.6, clamp 1-2.5); disabled when `dock.magnificationEnabled` is false (default). The target scale of a tile is the mean of the curve over its own slot (tile plus half the spacing each side; closed-form integral, `Magnify.slotScales`): the slots tile the line, so the row is displaced by the integral of the curve, tiles never overlap and nothing jumps at a slot boundary; separators stay at 1. The displayed scales follow the targets with an exponential smoothing in real time (`Magnify.step`, time constant `dock.magnificationTau` 26 ms, one frame step capped at `dock.magnificationMaxDt` 33 ms, driven by a `FrameAnimation` that runs only until settled; Reduce Motion snaps). Without the pointer the targets are 1, so the row settles back fully. A magnified icon also rises by `dock.magnificationLift` (0.1) of its growth, iconSize·(scale-1) (estimate: no macOS capture under design/reference to measure it; the running dot stays on the shelf). The layout is the unmagnified one, scaled; the shelf stays centred.
7. Autohide (`dock.autohide`, default false) is a state machine (`AutoHide.js`, pure; the Dock steps it from a `FrameAnimation` that stops while nothing can change). `visible` runs 1 to 0 and positions the shelf (eased with a smoothstep); Reduce Motion caps the two slide durations at `motion.reducedMax`.
   | State | Event | Next |
   |---|---|---|
   | shown | no inhibitor for `dock.hideGrace` (250 ms; the timer restarts whenever an inhibitor is set) | hiding |
   | hiding | any inhibitor, the pointer included (the slide reverses from its current position, no jump) | revealing |
   | hiding | `visible` reaches 0 after `dock.hideDuration` (300 ms) | hidden |
   | hidden | drag, popup, hold or keyboard inhibitor (never waits) | revealing |
   | hidden | the pointer on the edge strip (`dock.revealZone`, 2 px) for `dock.revealDwell` (120 ms) | revealing |
   | revealing | `visible` reaches 1 after `dock.revealDuration` (240 ms) | shown |
   Inhibitors that keep the Dock shown: an attention request (`attention`, `dock.attentionReveal` after the request), the pointer over it, a drag in progress (`dragFrom >= 0`), a Dock popup or menu (`Popups.kind == "dock"`), a press and hold on a tile, keyboard mode, and the test reveal hook. While hidden only the edge strip takes input (the input mask), so the pointer there means "at the edge". With autohide off the machine is shown at once. The hiding delay replaces the single 450 ms `dock.hideDelay` (removed). Fixture hook: `qs ipc call dock hidestate <screen>` prints "state visible".
8. Context menu (right click, or the Menu key on a focused item; `shell/overlay/DockMenu.qml`, a panel with a tail pointing at the icon): a running app's menu starts with its windows (macOS: only the windows of that tile, the same identity as the running dot; most recent first; titles as plain text collapsed to one line and elided at `menu.windowTitleMax` 40 like the menu bar's Window menu, the app name for an empty title; a check on the most recently focused window that is not minimized; "(minimized)" after the title of a minimized one) and a separator (`Launch.menuWindows`, pure, `tests/unit/tst_docklaunch.qml`); choosing one activates that window alone (`Compositor.activateAfterLayer`: Hyprland refuses to focus a window while an Exclusive layer surface exists, so it waits for `closelayer` of `grassfield-overlay`, at most `menu.layerWait` ms; `Compositor.activate` then restores it when minimized and switches to its Desktop, as a Dock click does) and nothing hands the focus back to the previous window (`FocusReturn.skip`). Then Open / New Window, the desktop entry's actions (`DesktopEntry.actions`), Options (macOS model: a running app has Keep in Dock, checked while kept, unchecking removes it once the app quits; a kept app that is not running has Remove from Dock and no Keep in Dock; a recent app that is not kept has Keep in Dock; Open at Login, checked while its autostart file exists; Show in Files), Show All Windows (`Compositor.bringAllToFront`), Hide (`Compositor.hideApp`), Quit (close all windows of the app). Option (Alt) variants follow the Alt key live while the menu is open (macOS; the menu holds the keyboard; `PopupMenu.altHeld`, set from the Alt key's own press and release so a submenu with the focus still reports it): Hide becomes Hide Others (`Compositor.hideOthers`, disabled when no other app has a visible window) and Quit becomes Force Quit, which asks "Force quit “App”?" / "Unsaved changes in this application will be lost." with the same destructive confirmation and kill path as the Grassfield menu's Force Quit… (`Popups.confirm` action `forcequit`, `Power.run`, `kill -9`) on the distinct client PIDs of the app's windows (`Launch.forceQuitPids`: unknown, init, negative PIDs are dropped; nothing is killed without PIDs). Open at Login writes or removes `<autostart dir>/<entry id>.desktop` (`AppLaunch.autostartFile`/`autostartText`: values escaped per the Desktop Entry spec, control characters in Exec refused, plain file names only; written by `overlay/write-autostart.sh`, temp file + rename; in a dev session `<dev>/apps-home/config/autostart`, never the owner's). Show in Files opens the folder of the entry's executable (`command -v`, `readlink -f`) through `Apps.openDetached`.
9. Trash icon: the theme's `user-trash` / `user-trash-full` (fallback `trash`/`trash-full` from branding), by `~/.local/share/Trash/files` emptiness (`find` at start and on hover, then on every `gio monitor` event). Its menu (right click or the Menu key; a press-and-hold still clicks) is the macOS one: Open (`Trash.open`) and Empty Trash… (disabled while the Trash is empty), which asks "Are you sure you want to permanently erase the items in the Trash?" / "You can’t undo this action." (destructive confirmation, Cancel focused, action `emptytrash` → `Power.run` → `Trash.emptyNow`). Emptying is the only deletion in `Trash`: a real session runs `gio trash --empty`; a dev session (`GRASSFIELD_DEV=1`) NEVER does (gio's trash:/// is served by the owner's session) and removes only the contents of the isolated trash `<dev>/apps-home/data/Trash/{files,info}` with `find -mindepth 1 -delete`, and nothing runs when the apps-home path is not a plain absolute `.../apps-home` (`AppLaunch.emptyTrashArgv`, `tests/unit/tst_applaunch.qml`; ADR-0011).
10. Keyboard: the dock takes keyboard focus only in keyboard mode (IPC `dock keyboard`, to be bound to a shortcut by the integrator): Tab/Shift+Tab move, Return opens, Menu key opens the item menu, Esc leaves the mode. Focus ring is 2 px accent and is drawn only in keyboard mode (a mouse click on a tile never shows it).

11. Minimized section (ADR-0002, master-prompt 5.6): right of the separator and before the Trash, one tile per window minimized by the shell (`Compositor.minimized`, newest last). Tile = app icon; in the `full` material profile a live `ScreencopyView` thumbnail with a small app-icon badge. Tooltip and accessible name: window title, ", minimized". Click, Return or Space restores the window to the current workspace and focuses it. Clicking an app icon whose windows are all minimized restores the most recent one; cycling skips minimized windows while the app has others. Closed windows leave the section.
12. Minimize paths: titlebar button (the plugin posts `grassfield>>{"type":"minimize-request","address":"…"}`; the address is validated as hex and mapped to a toplevel), Window menu, IPC `windows minimize` (bound to SUPER+M). `Compositor.minimize()` uses `hl.plugin.grassfield.minimize(address, x, y, w, h)` with the rectangle of the window's own tile (`Compositor.dockRect`: the Dock of the window's monitor, slot = separator + 1 + the window's index in the minimized list, global layout coordinates; each per-screen Dock registers with `Compositor.registerDock` and unregisters on destruction) when `Capabilities.has("minimize")`; otherwise it moves the window to `special:minimized`. Both branches record the window in the shell. `unminimize()` calls the plugin `restore(address, x, y, w, h)` toward the window's current tile on the focused monitor's Dock, or moves the window to the focused workspace, then activates it.

13. Launch and activation (owner report 2026-10-20, macOS 26 model; pure rules in `shell/dock/Launch.js`, tests `tests/unit/tst_docklaunch.qml`, nested `tests/visual/dock-launch.sh`):
    - Click on an app with no window: the icon hops until the app has a window or `dock.launchTimeout` (12 s) passes (`DockModel.bounceKeys`). One hop rises `dock.bounceHeightScale` (0.34) of the icon height and takes `dock.bounceDuration` (500 ms): ease out going up, ease in coming down. When the window appears the icon finishes its hop by landing (an OutBounce of `motion.normal`), the tile survives the rebuild because the tiles are a keyed list model (17). The first lifted frame is 20 ms after the click (measured in the shell). No bounce with Reduce Motion (the running dot still appears).
    - Press states, as implemented (`Dock.qml`, the left `TapHandler` of a tile):
      - While the button is held the icon is darker by `dock.pressDim` (0.25, brightness, offscreen layer only while pressed); the label goes away on the press and stays away until the pointer leaves the tile. The notification badge is a sibling of the icon, so the press-dim layer cannot clip it, and it hops with the icon.
      - Click: a left press released before `dock.menuHold` (550 ms) is a click. App and Files tiles: a press held past `dock.menuHold` opens the tile's Dock menu (macOS) and its release launches nothing (`menuByHold`). A press that turns into a drag is a drag (the drag cancels the tap handler, so no menu and no click).
      - Tiles without a Dock menu (Apps, Trash, minimized windows; the Trash has a menu on right click and the Menu key only, see 9) keep the click on release however long the button is held (`dock.clickHoldLimit`, 3600 s: Qt drops `tapped` after its long press, so these tiles get a limit they never reach).
      - Hold menu and drag (macOS: after a press-and-hold menu the rest of that press belongs to the menu): a press that opened the hold menu never moves a tile. The decision is taken when the drag handler would activate, from per-press state: `tile.menuByHold`, and `root.dragInterruptions` against the mark taken when the button went down (every interruption event of the drag-out list, see below, increments it). If either says so, the drag does not start: `win.dragFrom` stays -1, so nothing moves, no gap opens, the tooltip is unchanged, and the release changes no pin (the shell logs `drag-refused`). It is not an `enabled` guard on the drag handler: the tap handler cancels at the drag threshold (`pressed` becomes false), which would have re-enabled such a guard in the same event. The state is reset by the next press (`menuByHold` false, a new mark), so a deliberate drag on a later press, including one right after a hold menu was dismissed, reorders and unpins as usual. Nested trials (`tests/visual/dock-drag-interrupt.sh`): `holdmenu_then_drag_out` (release above the Dock) and `holdmenu_then_drag_sideways_reorder` (a running tile dragged along the shelf to before the pinned tile): pins unchanged, no `drag-start`, a logged `drag-refused`; `holdmenu_then_next_press_removes`; `interrupted_before_drag_sideways_refused` (the press is interrupted before the drag moves: refused). Fixtures IPC: `dock forcehold true` marks every press on an app tile as having opened the hold menu when it goes down, `dock forceinterrupt true` as interrupted, so the order (menu or interruption first, drag second) is deterministic.
      - An interrupted drag changes no pins: if an interruption arrives while a drag is active (a surface, popup, window, focus or workspace event, the lock, a cancelled grab), the drag is marked interrupted and its release, real or synthesized by Qt (a surface that takes the pointer makes Qt end the drag with a release that looks real; other interruptions leave the drag running until the user releases), never removes or reorders: `finishDrag` glides the tile back (`win.dragInterrupted`; it used to reorder). Nested trial `interrupted_during_drag_sideways_no_reorder` (Search opened 1.5 s into a sideways drag of a running tile: no reorder).
      - Right press (app and Files tiles): opens the Dock menu on the press, whatever the duration.
      - Cancelled click: a press that is taken away from the Dock never clicks. Qt then fires a tap with the button still down, so the Dock refuses it (`tap-refused-interrupted`). The cancelling events are a short explicit list, `Dock.qml` `root.cancelClicks()`, separate from the drag-out list (which over-cancels on purpose, owner batch 7): a shell surface opening over the Dock (Search, Overview, Apps, the switcher, a Dock or menu-bar menu, Notification Center, Control Center: `FocusReturn.surfaceOpened`, `Popups.kind` switching to a popup), the session lock, and Qt cancelling the grab (`TapHandler.canceled`, a cancelled grab on the handler). Window title changes and focus changes (`activewindowv2`) do NOT cancel a click (nested trial: eight clicks while the focused window retitled every 20 ms all tapped), and neither does a window opening or closing while the Dock still holds the press. But a window OPENING makes Qt end a held press by itself (a window closing never did: a 250 ms click while a window closed tapped, 3 of 3): the handler sees `pressed`, the window insertion (`objectInsertedPost` of the toplevel list), 35 ms later a tap, `pressed false` and a grab change with point state 8 (Released), no hover or cancel event, nothing that tells it from a real release while the button is still down. That release is not a click (macOS: a press the Dock did not finish does nothing): a press that began before a window insertion and whose tap comes less than `dock.clickWindowGuard` (150 ms) after it is refused (`tap-refused-window-event`), so neither a tap, an activation nor a menu happens and the user presses again. A real click that coincides with a window opening within 150 ms is lost the same way and costs one repeated click (for instance the second click of a fast double launch is lost when the first app's window maps while that click's button is down: 2 of 19 in the nested trial) (nested trial `mapdrop`: Trash and an app tile held 1 s with a window opened 0.1 s in).
      - Known limit: the hold menu is decided by a GUI-thread timer (`longPressThreshold`). When the Dock's thread stalls for 550 ms or more during a press, the timer can fire before the release is processed and a short click becomes the menu; Qt gives the handler no event timestamp to compare, so this cannot be told apart. The nested trials treat a press that the shell itself measured at 500 ms or more as a host stall and repeat it.
      - Known difference: on macOS you can press, hold, drag onto a menu item and release to pick it; here the menu is a separate popup that takes the pointer after the hold and the press is not handed over, so the menu items are picked with a second click. Ctrl+click is not handled (no Dock menu on it).
    - A second click on a tile that is launching does nothing (`Launch.click`: no second process), until a window appears or the timeout passes.
    - Click on a running app: every visible window of the app on the focused Desktop comes forward, the most recent last so that it is focused and in front (`Launch.activationPlan`); a click on the focused app does not cycle its windows. Windows of other Desktops stay where they are; when all its windows are on other Desktops, the most recent one is activated and the compositor switches to its Desktop (`Compositor.activate`; nested trial: Desktop 3 from Desktop 2). When all its windows are minimized, the most recent one is restored (the others stay minimized). An app tile with no window (a pinned or recent app that quit) is launched again through its desktop entry (single-instance apps open a new window).
    - The new window has the keyboard focus because Hyprland focuses a window when it maps (nested trial: the window of a Dock launch is the active window). The shell passes no `XDG_ACTIVATION_TOKEN`: Quickshell 0.3 has no API to create one (no activation type in the qmltypes); a launch in a real session through `uwsm-app` gets no token either. Limitation: an app that opens its window more than a few seconds after a click while the user has moved on to another window is not forced to the front.
    - Window animation (`config/hypr/grassfield/looknfeel.lua`): a new window scales from 94 % and fades in over 0.2 s (`windowsIn`, speed 2, `popin 94%`), closing is shorter (0.12 s, `popin 96%`).
    - Dev hooks (fixtures only): IPC `dock tiles` (keys in order); the shell logs `dock-launch: lift <ms since click> <px>` (bounce curve), `dock-launch: pressed true|false <epoch ms>`, `tap` and `menu-by-hold`, which `tests/visual/dock-launch.sh` reads (press and release times are the shell's, not guessed).
14. Badges: a red count bubble at the top right of an app icon from the notification history (`DockModel.badgeCount`: entries whose app name is the tile's name or entry id, case-insensitive; "99+" above 99). Read-only; the Dock never clears notifications.
15. Drag to reorder: pressing and dragging an app tile moves it; neighbours make room; on release `DockModel.reorder` returns the new pinned list (a running or recent app dropped before a pinned one becomes pinned). Dragged more than `dock.dragOutDistance` (56) above the shelf top a pinned or recent app that is not running shows a "Remove" capsule and, on release, leaves the Dock with a puff (`dock.poofDuration` 420, own drawing: fading circles) and is unpinned. A running app is never removed (it keeps its tile). While a pinned or recent app that is not running is dragged out past the threshold, the shelf closes the gap of the tile (the shelf narrows by one pitch around its centre, the tiles after it follow, `motion.fast`) and reopens when the tile is dragged back; on release the tiles animate from where they were shown. Tiles are not rebuilt while a tile is dragged (a window opening or closing waits for the release, then the latest state is applied), so a release always finishes the drag. Drag-out removal follows "cancel on interruption" (owner decision, events only, no timing or hover heuristics, no plugin). One flag per drag (`dragInterrupted`) is false when the drag starts (a press already interrupted when the drag would start does not start it at all, see 13) and is set, until the release is handled, by: a shell full-attention surface opening (`FocusReturn.surfaceOpened`: Search, Apps, switcher, popup host, Notification Center, widget menu, Overview); any shell popup changing (`Popups.kind`: Dock menu, menu-bar menus, Control Center, ...); the session lock (`FocusReturn.locked`); keyboard mode; Hyprland events relayed by `Compositor.interrupted` (window open, close or move, active window, workspace created, destroyed, changed or moved, special workspace, fullscreen, focused monitor, monitor added or removed, a layer opening from any client, banners included: over-cancelling is accepted); the toplevel list or the output list changing (an app quitting); and Qt cancelling or stealing the grab. Only the Dock's own drag feedback (Remove capsule, puff, tooltip) is excluded: it lives in the Dock window and reports none of these. A tile is removed only when ALL hold: a positive Released event point ends the exclusive grab, that release is outside the drop zone with the live drag offset agreeing, the item can be removed, and the drag was not interrupted. Qt ends an interrupted drag with a synthesized release that looks like a real one (fresh timestamp, any position), so a real release alone is not enough. After an interruption the tile glides back and the user may have to drag again (accepted). Esc cannot be seen by the Dock during a mouse drag (it has no keyboard focus); it cancels through keyboard mode only. A release inside the shelf never removes. `tests/visual/dock-drag-stress.sh` repeats the drag-out-and-back pattern 50 times (every fifth with a window opening during the drag) and asserts the pinned list never changes (`qs ipc call dock pinned`); it also runs every interruption trigger with the tile held above the Dock window and inside it, still and moving, and the deliberate removals (release far away, top edge, corner, slow, hold, flick, leave and re-enter, inside the window outside the drop zone), which must all remove. The drag is clamped so that the "Remove" capsule stays inside the window (`dock.dragArea` 168). An interrupted drag changes no pins at all: neither the removal nor the reorder is applied (`finishDrag` glides the tile back whenever `dragInterrupted` is set), and a release without interruption reorders and unpins as above.
16. File drops (macOS: a tile accepts a drop only if the app can open that document): a tile highlights and accepts files (text/uri-list) only when the entry's Exec has a file field code (`%f %F %u %U`, read from the raw `DesktopEntry.execString` through `DockModel.execArgs`: Quickshell's `command` has the codes stripped) AND its `MimeType` matches the type of every file (type from the shared MIME database by file name, with subclasses and aliases; an entry without `MimeType` accepts nothing; `DockModel.acceptsFiles`, data from `dock/mime-data.sh` via `Apps.mimeData`). The real type of every dropped path is looked up while hovering (`dock/file-types.sh`, for those paths only, async, cached for the drag by `Apps.hoverTypes`, cleared 1.5 s after the last tile is left): a directory is `inode/directory` whatever its name (a folder called `Photos.png` is a folder), a file keeps the type of its name, a file without a known name is typed by content through `gio info` (bounded, FIFOs and devices never opened). The tile's verdict (`DockModel.dropVerdict`) is `no` as soon as one known type does not match, `pending` while some paths are not resolved yet (the tile accepts without highlighting), `yes` when all match (highlight). A `no` verdict refuses the drag at the DnD level (`drag.accepted = false` on every motion event); the drop of a refused file is refused again at the drop, so the source never sees a performed drop. A source that hands its URI list over only at the drop leaves the verdict unknown (the tile accepts without highlighting and the drop is resolved afterwards; the source sees a performed drop even if the app then refuses: the only case left). Limitation: Qt only reports a new accept state on a motion event, so a pointer held perfectly still over the tile keeps the state of its last motion until the drop decides. Opening substitutes the field codes per the spec (`DockModel.commandsForFiles`: `%F %U` one launch with all files, `%f %u` one launch per file, `%u %U` as file:// URIs); nothing is ever appended to a command line (a file dropped on `foot` is refused, not run). Isolated environment in dev. If the URI list cannot be read while hovering, the tile highlights and the drop itself decides. Files dropped on the Trash are moved to the trash (`gio trash`, isolated trash in dev).
17. Recent applications (the recent list is not evaluated before the desktop entries and the hidden-entry list are loaded, so a hidden entry never takes a slot; `DockModel.recentsStep`) (macOS: their own section between the app tiles and the Trash section, set off by a separator): apps launched from the Dock, and apps that were running and quit while not kept in the Dock, are remembered (`dock.recent`, at most `dock.recentMax` 3, newest first, `DockModel.recentsAfter`: a pure function of the previous and current running sets, so the list is written only when it really changes and an app evicted by the cap is never re-added while it still runs). The tiles are a keyed `ListModel` updated by diffing on the tile key (`DockModel.diffKeys`: removals first, then inserts and moves, never a reset), so a delegate and its animations survive every rebuild. Whenever tiles are rebuilt they glide from where their key was to where it is now (an offset that animates to 0 on the delegate; the make-room offset of a dragged neighbour is a separate property, so the two never fight) (an app that quits without being kept in the Dock moves into the recents section instead of jumping; new tiles fade in; none with Reduce Motion; `DockModel.layoutTransition`). They are shown after a divider, before the separator and the Trash, when `dock.showRecents` is on (default true), without a dot. NoDisplay / hidden entries are never remembered or shown (`Apps.isListed`).
18. Minimize into the application icon (`dock.minimizeIntoApp`, default false): minimized windows get no tile of their own; the window animation targets (and leaves from) the tile of its app (`tileRect(index, adding, toplevel)`, `Compositor.dockRect(..., toplevel)`). Only the target rectangle changes; the animation itself is the compositor plugin's (funnel or shrink, `dock.minimizeEffect`).
19. Apps tile (macOS 26: Launchpad became "Apps" and keeps the first Dock tile): the first tile of every Dock is a fixed "Apps" tile (`DockModel.withApps`, kind `apps`, key `grid`; a rounded accent tile with our own symbolic `apps` glyph, no borrowed artwork), before the pinned apps. It is not an app: never pinned, dragged, removed, counted by reorder or the recents; no running dot, no menu. Tooltip and accessible name "Apps" (fr "Apps"). Click, Return or Space ask the shell root to toggle the Apps panel (`Dock.appsRequested` -> `AppsController.toggle()`, the same call as the `apps` IPC target and the hot corner).
20. Files tile (owner request 2026-10-20; macOS: the Finder is always the first Dock tile and cannot be removed): before the Apps tile every Dock has a fixed "Files" tile for `org.grassfield.Files` (`DockModel.splitFiles` / `withFixed`, kind `files`, key `files`; the own icon of the desktop entry (never the generic `system-file-manager`, a Finder lookalike in WhiteSur), `org.grassfield.Files` when it is missing). Order: Files, Apps, pinned apps, recents, separator, minimized, Trash. It is an app tile for everything but arrangement: running dot (it carries the windows of Files), launch bounce, click launches or raises, minimize into the tile, drops of files and folders (the entry's Exec has `%U`), right-click menu (Open/New Window, Options with only "Open at Login", Show All Windows, Hide, Quit). It is never pinned, dragged, removed, or counted by reorder, drag slots or recents (`appIndices` and `reorder` filter on kind `app`); a `org.grassfield.Files` id in `dock.pinned` or `dock.recent` is dropped from the list shown, so there is never a second tile. Without its desktop entry (not installed) a click opens the home folder through the open policy. Default `dock.pinned` is `["chromium","foot","org.grassfield.Settings"]` (Nautilus is not a default any more); a stored list equal to the old default `["foot","chromium","org.gnome.Nautilus"]` reads as the new default (`SettingsStore.dockPinned`, `DockModel.migratePinned`, nothing written back); any other list is the user's and is never touched. Tests: `tests/unit/tst_dockmodel.qml` (fixed tiles, windows, migration, bounce, keys).

21. Attention (macOS: an app that needs attention bounces its Dock icon until it is activated; NextKDE also brings an auto-hidden Dock out for a moment): Hyprland's `urgent>>ADDRESS` event is relayed by the platform layer (`Compositor.attention(address)`, `Compositor.addressOf(toplevel)`; the only place that reads compositor events). The pure state is `shell/dock/Attention.js` (tests `tests/unit/tst_dockattention.qml`): the set of urgent window addresses; a window that already has the focus never enters it; the tile of an app bounces while one of its windows is in it; the bounce stops when ANY window of that app gets the focus (the app is activated) and a window that closed leaves. The bounce is the launch hop repeated: rise `dock.attentionHeightScale` (0.34) of the icon, one hop of `dock.bounceDuration` every `dock.attentionPeriod` (1500 ms), until settled; the landing is the launch landing. Reduce Motion: no hop; a static accent plate (`dock.attentionHighlightOpacity` 0.35) sits behind the icon instead. The accessible name gains ", needs attention". An auto-hidden Dock comes out (AutoHide inhibitor `attention`, like a popup: it reveals at once and keeps the Dock shown) for `dock.attentionReveal` (3000 ms) after each new request, then hides after the usual grace. Known limit (integrator decision 2026-10-22): the session keeps `misc.focus_on_activate = true` (`config/hypr/grassfield/looknfeel.lua`), so Hyprland FOCUSES a window that requests activation (a bell with `bell.urgent`, most activation requests) and nothing bounces for those; the bounce shows for urgency without activation. `false` would also stop a link clicked in one app from bringing the browser forward, which macOS allows for a user-triggered activation: Hyprland 0.56.2 treats every activation request alike. The macOS model (focus on an activation that follows user input, attention otherwise) needs the compositor plugin (backlog). The trial switches only the nested instance with `hyprctl eval`. A bounce also stops when its window closes. Fixtures log `dock-attention: urgent|lift|settled`; nested trial `tests/visual/dock-attention.sh` (foot `-o bell.urgent=yes` printing BEL while another window has the focus).

## Dev notes: isolated app launches
In a `GRASSFIELD_DEV=1` session the shell runs on the owner's machine, so an app started from the Dock, Apps, Search, the Dock/app menus or by opening a desktop file must never use the owner's profiles (incident: Chromium launched from the nested Dock with the default profile). `Apps.launch(entryOrAction)` (`shell/services/Apps.qml`, the one launch path; helpers in `AppLaunch.js`, `tests/unit/tst_applaunch.qml`) starts the entry's `command` (Exec field codes dropped; `runInTerminal` through `xdg-terminal-exec`) with `Quickshell.execDetached({command, environment})` and `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` set to `<dev>/apps-home/{config,cache,state,data}` (`<dev>` is the parent of `GRASSFIELD_STATE_HOME`, i.e. `.dev/`, which is ignored by version control). `XDG_DATA_DIRS` is kept so system desktop entries and icons resolve. The Dock Trash tile (`gio open trash:///`) and the Quick Settings Wi-Fi editor (`nm-connection-editor`) go through `Apps.openDetached` too. File openers (`gio open`, `xdg-open`, `gtk-launch` for desktop files and Search results) get the same environment through `Apps.openDetached` / `Apps.openEnvironment`. Outside a dev session `DesktopEntry.execute()` is called unchanged. Check: launch foot from the nested Dock, then `tr '\0' '\n' < /proc/<pid>/environ | grep XDG_`.

## Known limitations
- Real pointer hover, edge reveal and tooltips were checked through IPC test hooks and keyboard focus, not with a physical pointer (wtype is keyboard only).
- Window cycling order is the foreign-toplevel list order. Hidden (special workspace) windows are brought back by Dock click or Show All. Live thumbnails of minimized windows depend on the compositor still rendering windows parked on a special workspace; not verified (the nested run used the `balanced` profile, icon tiles).
- Dock icons come from the installed theme and are not Grassfield artwork. No stacks, no left/right position.
- Drag and release were tested with `scripts/dev/pointer.sh` in ONE invocation (press, drag, release); a release sent from another invocation does not end the drag (a virtual pointer destroyed while pressed leaves the button down for the shell): a test harness artefact. The minimize animation toward the Dock is plugin work (not implemented); the fallback hides the window at once.
- Magnified icons grow upward; the shelf keeps its height and only widens.
