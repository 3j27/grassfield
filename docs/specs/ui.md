# grassfield-ui spec · shell-engineer · M1 (spike S1)

## macOS reference behavior (from design/reference/, described in words — no Apple images committed)
No reference material exists yet (F1 pending). Every measurement is an estimate and carries a `source` note in `ui/tokens/tokens.json`.

## Purpose and non-goals
Design system shared by the shell and (later) native apps: tokens, frosted material, appearance state and the M1 component set (Icon, PopupMenu/MenuItem/MenuSeparator, Slider, Toggle, Button, Tooltip). Non-goals: Qt Quick Controls style (M4), any Quickshell or Hyprland import, business logic.

## Functional requirements
1. `ui/tokens/tokens.json` is the single source of truth; `ui/tools/gen-tokens.py` generates `Tokens.qml`; `--check` exits 1 when stale.
2. `Appearance` exposes `dark` (default true), `transparency` (default 0.25), `reduceTransparency` (forces effective transparency 0), `reduceMotion` (durations capped at `motionReducedMax` = 100 ms).
3. `Material` tint alpha = `Appearance.tintAlpha(t)`: `1 - t * (1 - tintAlphaMin)` (0.85 at the default t = 0.25), clamped to `tintAlphaClamp` up to `tintClampUntil` (A2: 0.82 up to t = 0.6), then linear to `tintAlphaMin` at t = 1; adds top highlight, 1 px border and a gaussian shadow (`RectangularShadow`, QtQuick.Effects 6.9+, verified in Qt 6.11.2) masked so it never shows under the glass.
4. `Material` never blurs. The window declares `BackgroundEffect.blurRegion: Region { item: material; radius: material.radius }` when `material.blurActive`.
5. Font family Inter, fallback Noto Sans (first installed wins).
6. `Icon { name, color, size }` draws `branding/icons/symbolic/<name>.svg` (monochrome black) recolored with `MultiEffect` colorization (brightness 1 + colorization 1). `directory` is overridable for installed layouts.
6a. `TintedIcon { source, size, mode?, tint?, oversample? }` draws an application or file icon (an image URL: a theme icon path, `image://icon/<name>`, a file URL) in the user's icon appearance mode, see "Icon appearance modes". Never for symbolic UI glyphs (`Icon` keeps those) or content (thumbnails, notification pictures).
7. `PopupMenu { model }` with `model: [{id, text, shortcut?, iconName?, enabled?, checked?, destructive?, separator?, submenu?}]`; signals `activated(item)` and `closeRequested()`. Rows: 22 px, 6 px radius, accent highlight on hover and keyboard selection, right-aligned shortcut, chevron for submenus, disabled at `material.disabledOpacity`. Keys: Up/Down/Home/End, Return/Space, Right (open submenu), Left (close), Esc. The navigation model is `MenuNav.js` (pure).
8. `Slider` (value, from, to, stepSize, `moved(value)`; arrow/Home/End keys), `Toggle` (checked, `toggled(checked)`; Space/Return), `Button` (primary/destructive), `Tooltip` (text, shown, delay). All have `Accessible` role/name, focus ring 2 px, Reduce Motion aware.

## Icon appearance modes (ADR-0014 phase 1, provisional)
Every Grassfield surface that shows an app or file icon draws it through `TintedIcon`: Dock (tiles and minimized badge), Apps panel, Search results, desktop icons, Overview (Space tile icons, window name pill), the About and Force Quit panels, and the file-type icons of Grassfield Files (list, icon, column, gallery views and Get Info). The mode is `Appearance.iconMode`, fed from `icons.mode` by the shell (`Settings.iconMode`) and by Files and Settings (they read `grassfield.json` and follow it live, no restart). Not tinted, as in macOS: symbolic glyphs (`branding/icons/symbolic`), the Files sidebar and toolbar glyphs, file thumbnails, notification pictures, drag images. The macOS 26 model, what each mode does to a theme icon (every icon sits on a system plate and its artwork is recoloured by a fixed transform, as macOS does for icons that are not made for the mode; numbers are the `iconMode` token group):
- `default`: the icon as is. No effect item exists (`Loader.active` is false): no extra render pass, no cost.
- `dark` (macOS 26 Dark): the system plate is graphite (`darkPlateLuma` 0.13) with an edge highlight (`darkRim`, dark appearance only; fully opaque over the bare wallpaper) and the artwork sits on it scaled to `sysGlyphScale`, a little desaturated (`darkArtSaturation`) and mapped affinely in linear light from `darkArtLift` (black: it separates a little from the graphite) to `darkArtScale` (white); colour identity kept.
- `clear` (macOS 26 Clear): the plate is translucent glass (white at `clearPlateAlphaDark` in the dark appearance, smoked black at `clearPlateAlphaLight` in the light one, the material shows through) and the artwork a monochrome ink (near white in dark, near black in light) whose opacity is solved from the luminance of the artwork so that the colour on screen is affine in linear light between the glass and the ink (`clearBackdrop*` is the material the glass is assumed to sit on) and that never drops below `clearInkFloor` of the ink even for black artwork (a dark monochrome glyph such as Breeze's `network-wired`, `fcitx` or `zoom`, 1.1-1.4:1 on a dark panel in Default, stays about 2:1 against the plate); edge highlight `clearRim`. The same rule sets `darkArtLift` (Dark) and `tintedRampLowDark` (Tinted): measured with the model for a Breeze dark glyph (#232629): dark appearance 1.05-1.47:1 against the plate before, 2.0-2.2:1 now; light appearance 9-14:1 in Clear and Tinted, 2.2:1 in Dark. The price is internal contrast: black art against mid-grey art keeps about 1.6:1 in Clear (dark appearance) where Default has 5:1 (`tests/unit/tst_iconcontrast.qml`: a strong pair of 7:1 and more keeps 1.9:1, any pair from 4.5:1 up 1.5:1). Default has no plate, so a dark glyph keeps its 1.1-1.4:1 there: the theme's own limit (a dark Breeze variant in the dark appearance would be the fix, not a plate).
- `tinted` (macOS 26 Tinted): a dark tinted plate (`tintedPlateScale` of the tint's brightness) in the dark appearance, a light tinted plate (`tintedPlateMixLight`) in the light one; the luminance of the artwork is mapped onto a two-tone ramp of the tint (`tintedRampLow*` to `tintedRampHigh*`, one pair per appearance). `icons.tint` is the tint (default: the accent colour).
**Small icons keep the Default artwork (integrator decision 2026-10-22, the macOS model: small icons stay legible).** The modes apply from `iconMode.minSize` (24 px) up. Below it (the surfaces that draw icons through `TintedIcon` below 24 px: the Files list rows and sidebar, 16 to 22 px, the Force Quit rows, 18 px, the Overview pill, 20 px, and the Dock's minimized-window badge, about 19 px, which is given its drawn size) every mode draws the Default artwork at its own size, with no plate and no effect item (`TintedIcon.modeActive` is false, `effectiveMode` is `default`; a folder's symbol, plate model and recolour layer follow it). At 16 px a plate and a recolour made json, cpp, txt, sh and csv the same tile and left obs, systemsettings and a red glyph unreadable in Dark, Clear and Tinted. A2 asserts it (rule D) and `tst_iconmodes` checks the switch at 16 and 24 px.
**Known issue (opt-in effect modes only, Default unaffected):** opening the Apps panel in Dark, Clear or Tinted has one render-bound slow frame per opening (the first draw of about 100 effects in the window, 11-16 ms of render time; per-opening frames over 25 ms: 5-8 against 0-2 in Default and in the earlier MultiEffect build). Tried without effect: keeping effects alive across hides, pacing their creation, an asynchronous Loader, a cached texture per icon (a hidden ShaderEffectSource frees its texture). The measurements of the last runs were taken while other sessions loaded the machine (Default itself at 73-79 % of frames within 16 ms), so the figure needs a quiet-machine run (`tests/visual/icon-modes-apps-perf.sh 3`).

## Icon shader (system plate for every icon)
**One pass, no analysis (owner decision 2026-10-20).** `ui/Grassfield/Ui/shaders/icon.frag` (built to the committed `icon.frag.qsb` by `scripts/dev/build-shaders.sh`; `just check` runs `build-shaders.sh --check`, which fails when a `.frag` changed since its `.qsb` was built; the hash file `SOURCES.sha256` makes the check independent of the Qt version) draws, per fragment and for every icon in Dark, Clear and Tinted alike:
1. The system plate: a rounded square (`sysPlateInset` 0.04 of the box on each side, corner radius `sysPlateRadius` 0.225 of its side, the macOS squircle proportion): graphite in Dark (`darkPlateLuma`), glass in Clear (white at `clearPlateAlphaDark` in the dark appearance, smoked black at `clearPlateAlphaLight` in the light one, `clearPlateAlphaWallpaper` 0.7 over the bare wallpaper), tinted in Tinted (the tint at `tintedPlateScale` in dark, mixed `tintedPlateMixLight` to white in light).
2. The artwork: the icon texture scaled about the centre by `sysGlyphScale` 0.72 and recoloured by a fixed transform per mode that depends on the pixel alone (no neighbour, no analysis). Every map is increasing and works in linear light on the relative luminance `Y` of the pixel (gamma 2.2), so two parts of an icon that differ by a contrast ratio keep as much of it as the floor of the mode allows (black art mapped to a floor `lo` against white mapped to `hi` keeps `(hi + 0.05) / (lo + 0.05)` at most): Dark `d = mix(Y, c_lin, darkArtSaturation)`, `art = lift + (scale - lift) d` per channel in linear light (`lift` and `scale` are `darkArtLift` and `darkArtScale` as lightness, black stays darker than white art); Clear a flat ink (`clearInkDark` in the dark appearance, `clearInkLight` in the light one) with the opacity that makes `under + (ink - under) * Y` (dark; `1 - Y` for the smoked ink) the colour on screen, `under` being the plate over the assumed material, times the pixel's own opacity; Tinted `mix(tint * tintedRampLow, mix(tint, white, tintedRampHigh), Y)` in linear light with the pair of the appearance. The shader samples the texture once, unconditionally.
3. The rim: a thin edge highlight on the plate (white in Dark, the ink colour in Clear, the tint lifted toward white in Tinted; `darkRim`, `clearRim`, `tintedRim`). Its width is `rimWidth` px from `rimFullSize` (48) up and shrinks with the icon size but never below `rimMinWidth` (1.5 px); its opacity fades to `rimMinOpacity` on small icons (16 px list rows). Over the bare wallpaper the Dark rim is fully opaque.
The folder colour (`FolderIcon`) is applied by this shader to the artwork only (uniforms `folderTint` and the MultiEffect arithmetic), after the mode transform and before the plate is composited: the plate and its rim keep their look. Over the bare wallpaper (desktop icons: `TintedIcon.overWallpaper`, styled for the wallpaper whatever the window appearance, like the labels) Clear uses the strongly smoked plate so white ink and rim read on a white wallpaper and the plate edge on a black one; Clear over a material at transparency 0.8 or more is drawn the same way (`wallpaperLikeTransparency`), except over an opaque fill (`TintedIcon.overAccent`). Over the accent fill of a selected row (Search, Force Quit: `TintedIcon.overAccent`) the plate and the ink are the opposite of the fill (the row's text colour `accentText` says whether the accent is bright or dark): Clear gets an opaque plate (`clearPlateAlphaAccent` 0.9), dark with light ink on a bright accent and light with dark ink on a dark one, Dark keeps its graphite plate on both (on a dark accent the plate is 2.8:1 against it, with the white rim), Tinted takes the dark tinted plate on a bright accent and the light tinted plate on a dark one; Clear is never drawn as over the wallpaper there.
Why no analysis: the earlier design estimated each icon's own plate (16 probes, clustering, a second plate colour, a corner test, a stroke rule) in one then two passes. It misread icons (halos and ghost strokes from the same-hue stroke rule, a wedge of the HEY icon, a blank two-colour plate), compiled the clustering for about 2.8 s on a cold cache (a 3 s freeze at the first switch to an effect mode and after every Mesa update) and doubled the passes of every icon in the Apps panel. A uniform plate is how macOS treats an icon that is not made for the mode, and it cannot misread anything.
If the shader cannot be loaded (`.qsb` missing, compile error) `TintedIcon.effectFailed` becomes true, the plain image is shown at its normal size (the default look) and one warning is logged (`IconModes.warnOnce`); tested on a GPU scene graph (`test_missingShaderDrawsThePlainIcon`) and in `tst_iconmodes.qml`. The shader runs on the GPU scene graph only (ShaderEffect does nothing on the software renderer: the status stays uncompiled there).
Implementation: `IconModes.js` (pure: mode and tint validation, mode -> shader index), `IconEffect.qml` (one `ShaderEffect` per icon, its texture the icon `Image`'s own texture (the hidden image still renders for the effect), tokens as uniforms), `TintedIcon.qml` (an `Image` plus a `Loader` for the effect, active only while the icon is visible: a type icon hidden under a thumbnail or in a closed panel creates none). The effect is per visible icon, not per surface: a container layer would redraw the whole Dock or grid (labels, highlights, indicators) through the effect. In an effect mode the image keeps its decoded size (`size` x `oversample`) and only provides the texture, so the texture does not change while a surface scales the item (Dock magnification); the Dock decodes at `dock.iconOversample` (2.5, the largest magnification) in an effect mode, the Trash and minimized tiles included, and at 2 in default (`TintedIcon.defaultOversample`).
Settings key naming: ADR-0014 names the keys `appearance.iconMode` and `appearance.iconTint`, but contract version 1 already has `appearance` as a string (`dark|light|auto`), so a nested key cannot exist without a version bump. The keys are `icons.mode` and `icons.tint` (schema, defaults, `Store.js`, shell store, `tests/unit/tst_settingsstore.qml` parity, `tests/shell/settings_roundtrip`). `icons.tint` is validated as `accent` or `#rrggbb` by the schema `pattern` (`scripts/dev/check-schema.py` evaluates `pattern`; `tests/shell/check_schema_pattern.sh` checks that `"red"` is rejected) and by the stores. An invalid hand-edited value reads as the default.
Settings > Appearance > Icon appearance: four preview tiles (Default, Dark, Clear, Tinted; each a `TintedIcon` of the sample SVG `Grassfield.Ui/samples/icon-sample.svg` through the real shader, so a tile is what icons get; Settings has no theme-icon image provider, so the sample is a bundled file; selection = accent border on the tile, keyboard focus = a separate ring in the text colour set off by `previewFocusGap`; one focus stop, Left/Right/Up/Down change the choice, `Accessible` radio buttons) and a Tint colour row (Accent plus eight swatches; enabled only for Tinted, the caption names the colour or says why it is off). i18n en and fr.
A2 (icon recognisability, `tests/unit/tst_iconshader.qml`, run by `tests/visual/icon-a2.sh` / `just test-icons` as a client of the nested session because it needs a GPU scene graph; it skips on the offscreen software renderer): 12 own SVG fixtures (`tests/fixtures/icons`), 20 Breeze app icons (terminals, monitors, tile-shaped icons, plain glyphs) and 16 installed hicolor and Breeze icons read in place, never copied (a missing file is skipped), in Dark/Clear/Tinted. **The fixtures moved from WhiteSur to Breeze on 2026-10-21 and A2 was re-run on them the same day (`tests/visual/icon-a2.sh`, 15 cases: all pass with the measured limits below; a run of the whole list needs several attempts per case when the GPU is shared, stalled attempts are retried).** Scenarios: windows at 48, 32, 24 and 16 px in both appearances over black, grey and white wallpapers; the desktop (bare wallpaper black, grey, white and the default wallpaper's sky and hill colours, `overWallpaper`) at 48 px; the material at transparency 1.0 in every mode (Dark and Tinted included, floor 2.0) at 48, 24 and 16 px; Tinted with a bright yellow and a pink tint (windows and transparency 1.0, 32 px); the accent fill of a selected row; the folder model against the rendered pixels (at most 4/255 per channel; measured on the Breeze folder: 0/255 in every mode and appearance except Clear over the bare wallpaper, 10/255 before the model took the wallpaper plate into account, 0 after; 0 for the flat ones), a black folder on black (plate and rim stay in every mode) and the missing-shader fallback. Rule: I (inside) glyph-vs-plate >= floor of the default's (from 24 px up), E (outside) best of outline/plate/glyph vs background >= floor of the default's, S (separation) for artwork of one luminance, where floor(d) = 2.9 for d >= 3 else 0.9 d (Clear and Tinted: inside floor min(2, 0.9 d)). The outline band is the plate's inset, its rim and one pixel of antialiasing (3 to 4 px; the former 2 px band saw only the antialiased edge pixel of the plate, never the rim). Accent row: the plate pixel between the rim and the artwork has at least 4.5:1 against the accent in Clear (measured minimum 4.87 in both appearances; the old design measured 2.77:1 against 5.61:1 on main there) and 2.5:1 in Dark and Tinted (2.87 and 4.86). Rule D (icons below `iconMode.minSize`, 24 px): the icon of every mode is the Default artwork, pixel for pixel (largest channel difference 3/255 over the 16 px cells of both appearances, three wallpapers and transparency 1.0: measured and passing). Rule N (internal contrast), per-mode tiers, from 24 px up: when the default's lightest and darkest pixels in the middle of the artwork differ by 7:1 or more, Dark keeps 2.3:1, Tinted 1.9:1 and Clear 1.45:1; by 3:1 or more, 1.5:1, 1.4:1 and 1.25:1, each at least 0.05 below the measured lowest ( Dark 2.54 and 1.62, Tinted 2.18 and 1.50, Clear 1.52 and 1.31; no N exemption). Files selected row (`test_a2_filesSelectedRow`, icons of 24 px: from `iconMode.minSize` up): the mean contrast of the top 20 percent of the icon's pixels against the accent is at least 3:1, 2.5:1 for Dark. The effects now sample the Image's own texture (no offscreen pass per icon; captures identical to 1/255). The 96 percent target on the render thread is not reached; it needs the effects of a grid drawn once into a cached layer, not per icon.
The Dock decodes at `dock.iconOversample` (2.5) only in an effect mode (tiles, Trash and minimized tiles), 2 in default; default mode is identical to main.

## Folder colours (owner request 2026-10-19)
Folder icons are recoloured by a step separate from the icon modes: `FolderIcon { source, size, folderColor?, folderGlyph? }` wraps a `TintedIcon` (modes unchanged) and, when a colour applies, recolours it: in an icon mode the icon shader maps the luminance of the artwork onto the colour after the mode and before the system plate (`TintedIcon.recolor`; the plate and its rim keep their look, so a black folder keeps a visible plate on a black wallpaper), in default mode (and when the shader failed) a layer with one `FolderEffect` (`MultiEffect`, colorization 1 over the luminance of the theme's folder; tokens `folderIcon*`) does the same arithmetic. The colour is the folder's own (`folderColor`: `theme`, `accent`, `#rrggbb`, `""` = none) else the global `icons.folderColor` (`Appearance.folderColorSetting`); `theme` means the icon theme's own colour and creates no layer and no effect (`FolderStyle.recolors`). The optional `folderGlyph` is a `Text` over the effect, in a clipped box the size of the icon, at `folderIcon.glyphCenterY` with edge `glyphScale` x the icon: emoji opaque in their own colours, a plain symbol an engraved shade of the plate under it with >= 3:1 against the plate: the raw icon's pixels under the symbol are read once per icon file and size bucket and the plate of every mode, colour and appearance is computed from them with the arithmetic of the icon shader (its per-pixel recolouring, over the system plate) and of MultiEffect (`FolderPlate`, `FolderStyle.plateThrough`, `glyphShade`, `glyphMinContrast`; one engraving direction per icon mode; the symbol shows at once with an estimate and settles with a cross-fade; details and measurements in docs/specs/files.md); the symbol rule (one grapheme cluster, no control or bidi characters) is `FolderStyle.normalizeGlyph`, the same as the C++ side (one algorithm over generated data, `tests/fixtures/glyph-vectors.json`). `SwatchRow` puts its keyboard ring on the chosen swatch, else the first, as soon as it has the focus. `FolderStyle.js` is pure: validation (`theme|accent|#rrggbb`), precedence, folder icon names, the effect parameters from tokens, the parser of a folder's stored value, of `getfattr` output and of the per-user store (shell side, used by the desktop). The setting is `icons.folderColor` in the contract (schema `pattern`, defaults, `Store.js`, shell store, Files and Settings read it live); Settings > Appearance > Folder colour row (Theme, Accent, eight swatches). The per-folder storage, fallback and Customize Folder are specified in docs/specs/files.md. `tests/unit/tst_foldercolors.qml`.

## Accent colour (owner request 2026-10-20)

macOS reference: System Settings > Appearance > Accent colour: Multicolour (each app's own colour, for Grassfield the Grassfield green), Blue, Purple, Pink, Red, Orange, Yellow, Green, Graphite; the Highlight colour is Automatic (follows the accent).

Setting `accent.color` (schema enum, defaults, `Store.js`, shell store). The requested name `appearance.accent` cannot exist in contract version 1, where `appearance` is a string (`dark|light|auto`); the same constraint as the `icons.*` keys (ADR-0014), so the key is `accent.color`. `multicolor` (default, and any invalid hand-edited value) keeps the `accent` / `accentText` roles of the palette (own Grassfield green). Each other name has an own light and dark value and an `accentText` pair in the token groups `color.accentDark` / `color.accentLight` (roles `<name>`, `<name>Text`; own values, not copied); every pair has accentText on accent >= 4.5:1, and the selected-subtitle and lock-band roles hold for every accent (`tests/visual/test_contrast_tokens.py`, `test_every_accent_passes_the_accent_roles`). `Accent.js` (pure) resolves a setting; `Appearance.accentSetting` is fed by the shell (`Settings.accentColor`), Settings, Files and Preview from the same file, and `Appearance.colors`, `darkColors`, `lightColors` carry the chosen accent live, no restart: menu bar highlights, Dock, Control Center toggles, selections in Search, Apps and Notifications, Overview rings, focus rings, the icon tint `accent` and the folder colour `accent`. `Appearance.highlight` / `highlightText` (text selection) follow the accent (Automatic; there is no separate Highlight setting). Settings > Appearance > Accent colour: nine round swatches (SwatchRow), the chosen one ringed and marked, the caption names the hovered or chosen one. Tests: `tests/unit/tst_accent.qml`, `tests/shell/settings_apply.sh`.

## Known limitations
- All values are estimates, not measured from the reference.
- Blur strength cannot grow with the slider: it is compositor-defined; only the tint changes.
- Light appearance is untested visually. Inter is not installed yet (Noto Sans is used).
- The shadow cut-out mask shows a faint dark artifact at one corner in the light appearance (visible in `cc-light`); not fixed.
- Submenus declare no blur region of their own.
- Qt has no per-glyph font fallback list in QML; the family is chosen once at startup.
