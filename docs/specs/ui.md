# grassfield-ui spec · shell-engineer · M1 (spike S1)

## macOS reference behavior (from design/reference/, described in words — no Apple images committed)
No reference material exists yet (F1 pending). Every measurement is an estimate and carries a `source` note in `ui/tokens/tokens.json`.

## Purpose and non-goals
Design system shared by the shell and (later) native apps: tokens, frosted material, appearance state and the M1 component set (Icon, PopupMenu/MenuItem/MenuSeparator, Slider, Toggle, Button, Tooltip). Non-goals: Qt Quick Controls style (M4), any Quickshell or Hyprland import, business logic.

## Functional requirements
1. `ui/tokens/tokens.json` is the single source of truth; `ui/tools/gen-tokens.py` generates `Tokens.qml`; `--check` exits 1 when stale.
2. `Appearance` exposes `dark` (default true), `transparency` (default 0.25), `reduceTransparency` (forces effective transparency 0), `reduceMotion` (durations capped at `motionReducedMax` = 100 ms).
3. `Material` tint alpha = `Appearance.tintAlpha(t)`: `1 - t * (1 - tintAlphaMin)` (0.85 at the default t = 0.25), clamped to `tintAlphaClamp` up to `tintClampUntil` (A2: 0.82 up to t = 0.6), then linear to `tintAlphaMin` at t = 1; adds top highlight, 1 px border and a gaussian shadow (`RectangularShadow`, QtQuick.Effects 6.9+, verified in Qt 6.11.2) masked so it never shows under the glass.
4. `Material` never blurs. The window declares `BackgroundEffect.blurRegion: Region { item: material; radius: material.radius }` when `material.blurActive`.
5. Font family Inter, fallback Noto Sans (first installed wins).
6. `Icon { name, color, size }` draws `branding/icons/symbolic/<name>.svg` (monochrome black) recolored with `MultiEffect` colorization (brightness 1 + colorization 1). `directory` is overridable for installed layouts.
6a. `TintedIcon { source, size, mode?, tint?, oversample? }` draws an application or file icon (an image URL: a theme icon path, `image://icon/<name>`, a file URL) in the user's icon appearance mode, see "Icon appearance modes". Never for symbolic UI glyphs (`Icon` keeps those) or content (thumbnails, notification pictures).
7. `PopupMenu { model }` with `model: [{id, text, shortcut?, iconName?, enabled?, checked?, destructive?, separator?, submenu?}]`; signals `activated(item)` and `closeRequested()`. Rows: 22 px, 6 px radius, accent highlight on hover and keyboard selection, right-aligned shortcut, chevron for submenus, disabled at `material.disabledOpacity`. Keys: Up/Down/Home/End, Return/Space, Right (open submenu), Left (close), Esc. The navigation model is `MenuNav.js` (pure).
8. `Slider` (value, from, to, stepSize, `moved(value)`; arrow/Home/End keys), `Toggle` (checked, `toggled(checked)`; Space/Return), `Button` (primary/destructive), `Tooltip` (text, shown, delay). All have `Accessible` role/name, focus ring 2 px, Reduce Motion aware.

## Icon appearance modes (ADR-0014 phase 1, provisional)
Every Grassfield surface that shows an app or file icon draws it through `TintedIcon`: Dock (tiles and minimized badge), Apps panel, Search results, desktop icons, Overview (Space tile icons, window name pill), the About and Force Quit panels, and the file-type icons of Grassfield Files (list, icon, column, gallery views and Get Info). The mode is `Appearance.iconMode`, fed from `icons.mode` by the shell (`Settings.iconMode`) and by Files and Settings (they read `grassfield.json` and follow it live, no restart). Not tinted, as in macOS: symbolic glyphs (`branding/icons/symbolic`), the Files sidebar and toolbar glyphs, file thumbnails, notification pictures, drag images. The macOS 26 model, what each mode does to a theme icon (every icon sits on a system plate and its artwork is recoloured by a fixed transform, as macOS does for icons that are not made for the mode; numbers are the `iconMode` token group):
- `default`: the icon as is. No effect item exists (`Loader.active` is false): no extra render pass, no cost.
- `dark` (macOS 26 Dark): the system plate is graphite (`darkPlateLuma` 0.13) with an edge highlight (`darkRim`, dark appearance only; fully opaque over the bare wallpaper) and the artwork sits on it scaled to `sysGlyphScale`, darkened (`darkArtScale`) and a little desaturated (`darkArtSaturation`), its very dark parts lifted (`darkArtLift` over `darkArtLiftRange`) so they separate from the graphite; colour identity kept.
- `clear` (macOS 26 Clear): the plate is translucent glass (white at `clearPlateAlphaDark` in the dark appearance, smoked black at `clearPlateAlphaLight` in the light one, the material shows through) and the artwork a monochrome ink (near white in dark, near black in light) whose opacity follows its luminance (`clearAlphaFloor` up to full); edge highlight `clearRim`.
- `tinted` (macOS 26 Tinted): a dark tinted plate (`tintedPlateScale` of the tint's brightness) in the dark appearance, a light tinted plate (`tintedPlateMixLight`) in the light one; the luminance of the artwork is mapped onto a two-tone ramp of the tint (`tintedRampLow*` to `tintedRampHigh*`, one pair per appearance). `icons.tint` is the tint (default: the accent colour).
## Icon shader (system plate for every icon)
**One pass, no analysis (owner decision 2026-10-20).** `ui/Grassfield/Ui/shaders/icon.frag` (built to the committed `icon.frag.qsb` by `scripts/dev/build-shaders.sh`; `just check` runs `build-shaders.sh --check`, which fails when a `.frag` changed since its `.qsb` was built; the hash file `SOURCES.sha256` makes the check independent of the Qt version) draws, per fragment and for every icon in Dark, Clear and Tinted alike:
1. The system plate: a rounded square (`sysPlateInset` 0.04 of the box on each side, corner radius `sysPlateRadius` 0.225 of its side, the macOS squircle proportion): graphite in Dark (`darkPlateLuma`), glass in Clear (white at `clearPlateAlphaDark` in the dark appearance, smoked black at `clearPlateAlphaLight` in the light one, `clearPlateAlphaWallpaper` 0.7 over the bare wallpaper), tinted in Tinted (the tint at `tintedPlateScale` in dark, mixed `tintedPlateMixLight` to white in light).
2. The artwork: the icon texture scaled about the centre by `sysGlyphScale` 0.72 and recoloured by a fixed transform per mode that depends on the pixel alone (no neighbour, no analysis): Dark `d = (mix(L, c, darkArtSaturation)) * darkArtScale`, then `d + darkArtLift * (1 - smoothstep(0, darkArtLiftRange, luma(d)))` (black goes to `darkArtLift`, the transform stays monotonic); Clear a flat ink (`clearInkDark` in the dark appearance, `clearInkLight` in the light one) with opacity `mix(clearAlphaFloor, 1, L)` (dark) or `mix(clearAlphaFloor, 1, 1 - L)` (light) times the pixel's own; Tinted `mix(tint * tintedRampLow, mix(tint, white, tintedRampHigh), L)` with the pair of the appearance. `L` is the relative luma of the straight colour.
3. The rim: a thin edge highlight on the plate (white in Dark, the ink colour in Clear, the tint lifted toward white in Tinted; `darkRim`, `clearRim`, `tintedRim`). Its width is `rimWidth` px from `rimFullSize` (48) up and shrinks with the icon size but never below `rimMinWidth` (1.5 px); its opacity fades to `rimMinOpacity` on small icons (16 px list rows). Over the bare wallpaper the Dark rim is fully opaque.
The folder colour (`FolderIcon`) is applied by this shader to the artwork only (uniforms `folderTint` and the MultiEffect arithmetic), after the mode transform and before the plate is composited: the plate and its rim keep their look. Over the bare wallpaper (desktop icons: `TintedIcon.overWallpaper`, styled for the wallpaper whatever the window appearance, like the labels) Clear uses the strongly smoked plate so white ink and rim read on a white wallpaper and the plate edge on a black one; Clear over a material at transparency 0.8 or more is drawn the same way (`wallpaperLikeTransparency`), except over an opaque fill (`TintedIcon.overAccent`). Over the accent fill of a selected row (Search, Force Quit: `TintedIcon.overAccent`) the plate and the ink are the opposite of the fill (the row's text colour `accentText` says whether the accent is bright or dark): Clear gets an opaque plate (`clearPlateAlphaAccent` 0.9), dark with light ink on a bright accent and light with dark ink on a dark one, Dark and Tinted take the dark plate on a bright accent and the light tinted plate on a dark one; Clear is never drawn as over the wallpaper there.
Why no analysis: the earlier design estimated each icon's own plate (16 probes, clustering, a second plate colour, a corner test, a stroke rule) in one then two passes. It misread icons (halos and ghost strokes from the same-hue stroke rule, a wedge of the HEY icon, a blank two-colour plate), compiled the clustering for about 2.8 s on a cold cache (a 3 s freeze at the first switch to an effect mode and after every Mesa update) and doubled the passes of every icon in the Apps panel. A uniform plate is how macOS treats an icon that is not made for the mode, and it cannot misread anything.
If the shader cannot be loaded (`.qsb` missing, compile error) `TintedIcon.effectFailed` becomes true, the plain image is shown at its normal size (the default look) and one warning is logged (`IconModes.warnOnce`); tested on a GPU scene graph (`test_missingShaderDrawsThePlainIcon`) and in `tst_iconmodes.qml`. The shader runs on the GPU scene graph only (ShaderEffect does nothing on the software renderer: the status stays uncompiled there).
Implementation: `IconModes.js` (pure: mode and tint validation, mode -> shader index), `IconEffect.qml` (one `ShaderEffect` per icon, its texture a child `ShaderEffectSource` of the icon image, tokens as uniforms), `TintedIcon.qml` (an `Image` plus a `Loader` for the effect, active only while the icon is visible: a type icon hidden under a thumbnail or in a closed panel creates none). The effect is per visible icon, not per surface: a container layer would redraw the whole Dock or grid (labels, highlights, indicators) through the effect. In an effect mode the image keeps its decoded size (`size` x `oversample`) and only provides the texture, so the texture does not change while a surface scales the item (Dock magnification); the Dock decodes at `dock.iconOversample` (2.5, the largest magnification) in an effect mode, the Trash and minimized tiles included, and at 2 in default (`TintedIcon.defaultOversample`).
Settings key naming: ADR-0014 names the keys `appearance.iconMode` and `appearance.iconTint`, but contract version 1 already has `appearance` as a string (`dark|light|auto`), so a nested key cannot exist without a version bump. The keys are `icons.mode` and `icons.tint` (schema, defaults, `Store.js`, shell store, `tests/unit/tst_settingsstore.qml` parity, `tests/shell/settings_roundtrip`). `icons.tint` is validated as `accent` or `#rrggbb` by the schema `pattern` (`scripts/dev/check-schema.py` evaluates `pattern`; `tests/shell/check_schema_pattern.sh` checks that `"red"` is rejected) and by the stores. An invalid hand-edited value reads as the default.
Settings > Appearance > Icon appearance: four preview tiles (Default, Dark, Clear, Tinted; each a `TintedIcon` of the sample SVG `Grassfield.Ui/samples/icon-sample.svg` through the real shader, so a tile is what icons get; Settings has no theme-icon image provider, so the sample is a bundled file; selection = accent border on the tile, keyboard focus = a separate ring in the text colour set off by `previewFocusGap`; one focus stop, Left/Right/Up/Down change the choice, `Accessible` radio buttons) and a Tint colour row (Accent plus eight swatches; enabled only for Tinted, the caption names the colour or says why it is off). i18n en and fr.
A2 (icon recognisability, `tests/unit/tst_iconshader.qml`, run by `scripts/dev/test-icons.sh` / `just test-icons` as a client of the nested session because it needs a GPU scene graph; it skips on the offscreen software renderer): 12 own SVG fixtures (`tests/fixtures/icons`), 18 WhiteSur icons when `.dev` has them and 16 installed non-WhiteSur icons read in place, never copied (hicolor and breeze; a missing file is skipped), in Dark/Clear/Tinted. Scenarios: windows at 48, 32, 24 and 16 px in both appearances over black, grey and white wallpapers; the desktop (bare wallpaper black, grey, white and the default wallpaper's sky and hill colours, `overWallpaper`) at 48 px; the material at transparency 1.0 in every mode (Dark and Tinted included, floor 2.0) at 48, 24 and 16 px; Tinted with a bright yellow and a pink tint (windows and transparency 1.0, 32 px); the accent fill of a selected row; the folder model against the rendered pixels (at most 4/255 per channel; measured 1/255 for the WhiteSur folder, 0 for the flat ones), a black folder on black (plate and rim stay in every mode) and the missing-shader fallback. Rule: I (inside) glyph-vs-plate >= floor of the default's (from 24 px up), E (outside) best of outline/plate/glyph vs background >= floor of the default's, S (separation) for artwork of one luminance, where floor(d) = 2.9 for d >= 3 else 0.9 d (Clear and Tinted: inside floor min(2, 0.9 d)). The outline band is the plate's inset, its rim and one pixel of antialiasing (3 to 4 px; the former 2 px band saw only the antialiased edge pixel of the plate, never the rim). Accent row: the plate pixel between the rim and the artwork has at least 4.5:1 against the accent in Clear (measured minimum 4.87 in both appearances; the old design measured 2.77:1 against 5.61:1 on main there) and 2.5:1 in Dark and Tinted (2.87 and 4.86). Remaining limits, logged and not failed, all with the rim not seen by the metric or a plate of the mode's own colour against a mid-grey material: Dark in the dark appearance over a light wallpaper (the graphite plate is 1.1 to 1.6:1 against that material) for artwork that is dark overall (foot 2.23, obs 2.47, kdenlive 2.45, dark-plate-light-border 2.53, dark-glyph-no-plate 2.80, logo-no-plate 2.86, same-tone-glyph 2.84 against a floor of 2.9); Tinted dark appearance foot 2.78 and btop 2.25 at 16-24 px, a bright yellow tint in the light appearance (white page 2.35, Calendar 2.14 at 32 px); Basecamp (a sky and a hill of nearly equal luminance) Clear and Tinted glyph-vs-plate 1.29 to 1.43 against 1.71; and at transparency 1.0 and 16 px Dark 1.68 to 2.0, Tinted foot 1.89, Clear 1.85 to 1.94 (floor 2.0). These are properties of a uniform plate with a luminance-only recolouring, accepted by the owner decision of 2026-10-20; the exemption list of the analysis design (full-bleed logos, near-black glyphs, Nautilus) is gone because those icons now sit on the plate like all others. `scripts/dev/test-icons.sh` runs each case in a process of its own under a watchdog (240 s per attempt, up to 4 attempts; a stalled renderer under GPU contention is retried, a real failure is not).
Measurements (nested session, WhiteSur, 2026-10-20, this shader): cold compile with every cache off (`QSG_RHI_DISABLE_SHADER_DISK_CACHE=1`, `MESA_SHADER_CACHE_DISABLE=true`), frame in which the effect first draws: 20 ms (a 17 ms frame is normal: about 3 ms of compile) against 2954 ms for the previous analysis + icon shaders. Shell start in Tinted: first frame 0.45 s after launch, slowest frame 23 ms, no warning. Files scroll over 1000 folders (`tests/visual/icon-modes-perf.sh`, 60 notches each way): 1239 frames, none over 33 ms on the GUI or render thread in every mode, slowest render frame 17-19 ms (default 18 ms), 94-99 percent of render frames within 16 ms (Clear 94.1, default 98.7), CPU 3-4 s in every mode. The Apps panel opened 5 times: GUI thread 96.2-96.8 percent of frames within 16 ms (default 100.0), slowest 22-33 ms (default 16 ms); render thread 93.1-93.9 percent within 16 ms (default 97.6), slowest 23-34 ms (default 18 ms). The Dock decodes at `dock.iconOversample` (2.5) only in an effect mode (tiles, Trash and minimized tiles), 2 in default; default mode is identical to main.

## Folder colours (owner request 2026-10-19)
Folder icons are recoloured by a step separate from the icon modes: `FolderIcon { source, size, folderColor?, folderGlyph? }` wraps a `TintedIcon` (modes unchanged) and, when a colour applies, recolours it: in an icon mode the icon shader maps the luminance of the artwork onto the colour after the mode and before the system plate (`TintedIcon.recolor`; the plate and its rim keep their look, so a black folder keeps a visible plate on a black wallpaper), in default mode (and when the shader failed) a layer with one `FolderEffect` (`MultiEffect`, colorization 1 over the luminance of the theme's folder; tokens `folderIcon*`) does the same arithmetic. The colour is the folder's own (`folderColor`: `theme`, `accent`, `#rrggbb`, `""` = none) else the global `icons.folderColor` (`Appearance.folderColorSetting`); `theme` means the icon theme's own colour and creates no layer and no effect (`FolderStyle.recolors`). The optional `folderGlyph` is a `Text` over the effect, in a clipped box the size of the icon, at `folderIcon.glyphCenterY` with edge `glyphScale` x the icon: emoji opaque in their own colours, a plain symbol an engraved shade of the plate under it with >= 3:1 against the plate: the raw icon's pixels under the symbol are read once per icon file and size bucket and the plate of every mode, colour and appearance is computed from them with the arithmetic of the icon shader (its per-pixel recolouring, over the system plate) and of MultiEffect (`FolderPlate`, `FolderStyle.plateThrough`, `glyphShade`, `glyphMinContrast`; one engraving direction per icon mode; the symbol shows at once with an estimate and settles with a cross-fade; details and measurements in docs/specs/files.md); the symbol rule (one grapheme cluster, no control or bidi characters) is `FolderStyle.normalizeGlyph`, the same as the C++ side (one algorithm over generated data, `tests/fixtures/glyph-vectors.json`). `SwatchRow` puts its keyboard ring on the chosen swatch, else the first, as soon as it has the focus. `FolderStyle.js` is pure: validation (`theme|accent|#rrggbb`), precedence, folder icon names, the effect parameters from tokens, the parser of a folder's stored value, of `getfattr` output and of the per-user store (shell side, used by the desktop). The setting is `icons.folderColor` in the contract (schema `pattern`, defaults, `Store.js`, shell store, Files and Settings read it live); Settings > Appearance > Folder colour row (Theme, Accent, eight swatches). The per-folder storage, fallback and Customize Folder are specified in docs/specs/files.md. `tests/unit/tst_foldercolors.qml`.

## Degraded behavior
Compositor without ext-background-effect: surfaces stay tinted but unblurred (fallback via Hyprland layer rules is not implemented yet).

## Automated tests · Manual verification steps
`scripts/dev/test.sh`; nested `scripts/dev/shot.sh` with a striped wallpaper behind the bar at `material.transparency` 1 vs 0.

## Performance · Accessibility · i18n
Each Material with a shadow adds two offscreen layers and a MultiEffect mask; not measured (gate P* not run). Shell RSS after the M1 scenarios: see the S2 report. Legibility gate A2 not measured. Strings live in surfaces via `qsTr()`.

## Known limitations
- All values are estimates, not measured from the reference.
- Blur strength cannot grow with the slider: it is compositor-defined; only the tint changes.
- Light appearance is untested visually. Inter is not installed yet (Noto Sans is used).
- The shadow cut-out mask shows a faint dark artifact at one corner in the light appearance (visible in `cc-light`); not fixed.
- Submenus declare no blur region of their own.
- Qt has no per-glyph font fallback list in QML; the family is chosen once at startup.
