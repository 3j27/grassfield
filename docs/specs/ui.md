# grassfield-ui spec · shell-engineer · M1 (spike S1)

## macOS reference behavior (from design/reference/, described in words — no Apple images committed)
No reference material exists yet (F1 pending). Every measurement is an estimate and carries a `source` note in `ui/tokens/tokens.json`.

## Purpose and non-goals
Design system shared by the shell and (later) native apps: tokens, frosted material, appearance state and the M1 component set (Icon, PopupMenu/MenuItem/MenuSeparator, Slider, Toggle, Button, Tooltip). Non-goals: Qt Quick Controls style (M4), any Quickshell or Hyprland import, business logic.

## Functional requirements
1. `ui/tokens/tokens.json` is the single source of truth; `ui/tools/gen-tokens.py` generates `Tokens.qml`; `--check` exits 1 when stale.
2. `Appearance` exposes `dark` (default true), `transparency` (default 0.25), `reduceTransparency` (forces effective transparency 0), `reduceMotion` (durations capped at `motionReducedMax` = 100 ms).
3. `Material` tint alpha = `Appearance.tintAlpha(t)`: `1 - t * (1 - tintAlphaMin)` (0.85 at the default t = 0.25), clamped to `tintAlphaClamp` up to `tintClampUntil` (A2: 0.82 up to t = 0.6), then linear to `tintAlphaMin` at t = 1; adds top highlight, 1 px border and a gaussian shadow (`RectangularShadow`, QtQuick.Effects 6.9+, verified in Qt 6.11.2) masked so it never shows under the glass.
4. `Material` never blurs. The window declares `BackgroundEffect.blurRegion: Region { item: material; radius: material.radius }` when `material.blurActive`.
5. Font family Inter, fallback Noto Sans (first installed wins).
6. `Icon { name, color, size }` draws `branding/icons/symbolic/<name>.svg` (monochrome black) recolored with `MultiEffect` colorization (brightness 1 + colorization 1). `directory` is overridable for installed layouts.
6a. `TintedIcon { source, size, mode?, tint?, oversample? }` draws an application or file icon (an image URL: a theme icon path, `image://icon/<name>`, a file URL) in the user's icon appearance mode, see "Icon appearance modes". Never for symbolic UI glyphs (`Icon` keeps those) or content (thumbnails, notification pictures).
7. `PopupMenu { model }` with `model: [{id, text, shortcut?, iconName?, enabled?, checked?, destructive?, separator?, submenu?}]`; signals `activated(item)` and `closeRequested()`. Rows: 22 px, 6 px radius, accent highlight on hover and keyboard selection, right-aligned shortcut, chevron for submenus, disabled at `material.disabledOpacity`. Keys: Up/Down/Home/End, Return/Space, Right (open submenu), Left (close), Esc. The navigation model is `MenuNav.js` (pure).
8. `Slider` (value, from, to, stepSize, `moved(value)`; arrow/Home/End keys), `Toggle` (checked, `toggled(checked)`; Space/Return), `Button` (primary/destructive), `Tooltip` (text, shown, delay). All have `Accessible` role/name, focus ring 2 px, Reduce Motion aware.

## Icon appearance modes (ADR-0014 phase 1, provisional)
Every Grassfield surface that shows an app or file icon draws it through `TintedIcon`: Dock (tiles and minimized badge), Apps panel, Search results, desktop icons, Overview (Space tile icons, window name pill), the About and Force Quit panels, and the file-type icons of Grassfield Files (list, icon, column, gallery views and Get Info). The mode is `Appearance.iconMode`, fed from `icons.mode` by the shell (`Settings.iconMode`) and by Files and Settings (they read `grassfield.json` and follow it live, no restart). Not tinted, as in macOS: symbolic glyphs (`branding/icons/symbolic`), the Files sidebar and toolbar glyphs, file thumbnails, notification pictures, drag images. The macOS 26 model, what each mode does to a theme icon (the theme has no separate glyph layer, so the effect is an approximation; numbers are the `iconMode` token group):
- `default`: the icon as is. No effect item exists (`Loader.active` is false): no extra render pass, no cost.
- `dark` (macOS 26 Dark): the plate becomes near black (graphite, `darkPlateLuma` 0.13) keeping its hue and gradient; a saturated plate keeps `darkChromaKeep` of its brightness (a full-bleed logo must not turn navy); a plate already darker is kept. Glyphs: neutral glyphs on a light plate invert (black -> `darkGlyphLuma`), coloured glyphs keep their colour (dark ones brightened by `darkGlyphBoost`), white glyphs stay white. A thin edge highlight (`darkRim`, dark appearance only) keeps the plate visible on a dark material.
- `clear` (macOS 26 Clear): the plate becomes translucent glass (white at `clearPlateAlphaDark` in the dark appearance, smoked black at `clearPlateAlphaLight` in the light one, the material shows through) and the glyph a monochrome ink (near white in dark, near black in light) whose shading follows the glyph's colour distance from the plate (`clearDetail`); edge highlight `clearRim`.
- `tinted` (macOS 26 Tinted): a dark tinted plate (`tintedPlateScale` of the tint's brightness) with a tint-coloured glyph lifted toward white (dark appearance); a light tinted plate (`tintedPlateMixLight`) with a darkened tint glyph (`tintedGlyphShadeLight`, light appearance). The glyph's own shading modulates the tint (`tintedDetail`). Not a bright tint-coloured plate. `icons.tint` is the tint (default: the accent colour).
## Icon shader (plate detection)
`ui/Grassfield/Ui/shaders/icon.frag` (built to the committed `icon.frag.qsb` by `scripts/dev/build-shaders.sh`; `just check` runs `build-shaders.sh --check`, which fails when a `.frag` changed since its `.qsb` was built; the hash file `SOURCES.sha256` makes the check independent of the Qt version). Third-party icons have no layers, so the shader separates plate and glyph per pixel:
1. Plate estimate: 16 probes on a ring at about 0.36 from the centre (inside a plate and inside the thin light border some icons have at their edge, which starts near 0.40, but away from most glyphs). The plate is the dominant colour cluster of the probes (the probe with most neighbours within `plateToleranceLow`, weighted by opacity; probes on a glyph fall outside it) and its strength is the share of probes in the cluster (`plateAlphaLow..High`): a multi-coloured logo or a transparent background has no dominant cluster, hence no plate. The first version sampled the edge (0.41) and read a light border as the plate (the installed hicolor foot icon went light grey in Dark, white in Clear); inner probes (0.2/0.33) read the glyph of glyph-heavy icons as the plate.
2. Plate membership: a pixel is plate when its RGB distance to the plate colour is under `plateToleranceLow` (soft up to `plateToleranceHigh`), times the strength; the rest is glyph. A plate gradient (distance about 0.2) stays plate; a white glyph on a blue plate (0.8) is glyph.
3. Per-mode mapping (above), then the edge highlight on the shape boundary (alpha taps at `rimWidth` px).
System plate (owner decision 2026-10-19: in Clear and Tinted every icon sits on a system plate, nothing may vanish): a rounded square (`sysPlateInset` 0.04 of the box, radius `sysPlateRadius` 0.225 of its side, the macOS squircle proportion) behind the artwork, glass in Clear (white in the dark appearance, smoked in the light one, `clearPlateAlpha*`), tinted in Tinted (dark tint in dark, light tint in light), with an edge highlight. An icon whose own plate is a rounded square filling the box (corner probes and edge-midpoint probes opaque, and a dominant colour cluster, or two clusters for a two-colour plate such as the split face of Nautilus) keeps it, recoloured; every other icon (a logo, a mascot blob, a page, a round icon) is drawn smaller (`sysGlyphScale` 0.72) on the system plate, weighted by 1 minus its own-plate strength. Dark adds no plate (macOS Dark does not). Over the bare wallpaper (desktop icons: `TintedIcon.overWallpaper`, styled for the wallpaper whatever the window appearance, like the labels) Clear uses a strongly smoked plate (`clearPlateAlphaWallpaper` 0.7) so white ink and rim read on a white wallpaper and the plate edge on a black one.
No plate (strength low; a white page, a logo): Dark darkens a large light neutral area like a plate (the local average colour, a blurred read of the texture, is the virtual plate) and inverts neutral dark glyphs inside it; Clear and Tinted shade the ink by the pixel's luma against the icon's mean luma (`0.3 + 0.7 * L / (1.5 * mean)`), so the average part gets a bright ink and the darkest parts dim, which keeps a dark glyph on a dark material visible. The edge highlight (rim) keeps its width in logical pixels (`rimWidth`) from `rimFullSize` (48) up and shrinks and fades on smaller icons (16 px list rows). If the shader cannot be loaded (`.qsb` missing, compile error) `TintedIcon.effectFailed` becomes true, the plain image is shown (the default look) and one warning is logged (`IconModes.warnOnce`); tested on a GPU scene graph (`test_missingShaderDrawsThePlainIcon`) and in `tst_iconmodes.qml`.
Limits: a one-colour logo filling the canvas with holes (the Discord icon of the default WhiteSur variant) cannot be told from a coloured plate and is drawn as a plate (Dark keeps half of its brightness; Tinted/Clear give it a rim, which makes it pass the outside rule); an icon split in two plate colours (Nautilus) gets one of them as plate; Clear and Tinted are monochrome, so a glyph that differs from its plate only by hue keeps that difference only as luminance (see the measured exemptions in A2 below); a near-black glyph without a plate keeps only its dark-range luminance detail. The shader runs on the GPU scene graph only (ShaderEffect does nothing on the software renderer: the status stays uncompiled there).
Implementation: `IconModes.js` (pure: mode and tint validation, mode -> shader index), `IconEffect.qml` (one `ShaderEffect` per icon, its texture a child `ShaderEffectSource` of the icon image, tokens as uniforms), `TintedIcon.qml` (an `Image` plus a `Loader` for the effect, active only while the icon is visible: a type icon hidden under a thumbnail or in a closed panel creates none). The effect is per visible icon, not per surface: a container layer would redraw the whole Dock or grid (labels, highlights, indicators) through the effect. In an effect mode the image keeps its decoded size (`size` x `oversample`) and only provides the texture, so the texture does not change while a surface scales the item (Dock magnification); the Dock decodes at `dock.iconOversample` (2.5, the largest magnification) so it never upscales.
Settings key naming: ADR-0014 names the keys `appearance.iconMode` and `appearance.iconTint`, but contract version 1 already has `appearance` as a string (`dark|light|auto`), so a nested key cannot exist without a version bump. The keys are `icons.mode` and `icons.tint` (schema, defaults, `Store.js`, shell store, `tests/unit/tst_settingsstore.qml` parity, `tests/shell/settings_roundtrip`). `icons.tint` is validated as `accent` or `#rrggbb` by the schema `pattern` (`scripts/dev/check-schema.py` evaluates `pattern`; `tests/shell/check_schema_pattern.sh` checks that `"red"` is rejected) and by the stores. An invalid hand-edited value reads as the default.
Settings > Appearance > Icon appearance: four preview tiles (Default, Dark, Clear, Tinted; each a `TintedIcon` of the sample SVG `Grassfield.Ui/samples/icon-sample.svg` through the real shader, so a tile is what icons get; Settings has no theme-icon image provider, so the sample is a bundled file; selection = accent border on the tile, keyboard focus = a separate ring in the text colour set off by `previewFocusGap`; one focus stop, Left/Right/Up/Down change the choice, `Accessible` radio buttons) and a Tint colour row (Accent plus eight swatches; enabled only for Tinted, the caption names the colour or says why it is off). i18n en and fr.
A2 (icon recognisability, `tests/unit/tst_iconshader.qml`, run by `scripts/dev/test-icons.sh` / `just test-icons` as a client of the nested session because it needs a GPU scene graph; it skips on the offscreen software renderer): 9 own SVG fixtures (`tests/fixtures/icons`: light plate with dark glyph, blue plate with white glyph, graphite plate with red glyph, light plate with colour glyph, logo without plate, near-black glyph without plate, a one-colour mascot-like blob logo, dark plate inside a thin light border, white document page), 17 WhiteSur icons when `.dev` has them and 15 installed non-WhiteSur icons read in place, never copied (hicolor and breeze; a missing file is skipped), in Dark/Clear/Tinted, at 48, 32, 24 and 16 px, both appearances, over the default material on black, grey and white wallpapers, plus the desktop (bare wallpaper black, grey, white and the default wallpaper's sky and hill colours, `overWallpaper`) at 48 px. The icon's pixels are those that differ from the background in a rendering over it or over its complement (a glass plate equal to the background in one is still found in the other). Rule: I (inside) glyph-vs-plate >= floor of the default's (from 24 px up: at 16 px the edge highlight and the anti-aliasing fill the measured ring), E (outside) best of outline/plate/glyph vs background >= floor of the default's, where floor(d) = 2.9 for d >= 3 else 0.9 d (Clear and Tinted are monochrome: inside floor min(2, 0.9 d)); the outline is the 90th percentile of the contrast of the pixels of the 2 px edge band (a maximum would let a few pixels carry an invisible edge). Result: 0 unexpected failures; the full-bleed logo, the near-black glyph, logo-no-plate, btop, Image Viewer-like and Nautilus cases that were exempt before now pass in Clear and Tinted, because every icon sits on a system plate. Remaining limits, logged and not failed (worst measured value against the floor), all in Dark, which keeps the icon's own structure, plus marginal desktop values: breeze text editor Dark outside 1.51 (default 9.18; the darkened page is near the dark material and its frame is a 1 px grey line); Nautilus Dark inside 2.26 (default 5.64) and outside 1.87 at 16 px; kdenlive Dark inside 2.0 / outside 2.2 (default 3.5 / 3.83) and Tinted at 16 px outside 2.49 (floor 2.6); mascot blob Dark inside 1.89 / outside 1.97 at 24 px; on the desktop breeze calculator Dark 1.86 (default 2.65), mpv, Evince, white page and VLC Dark 2.5-2.8 (floor 2.9), hicolor LibreOffice Tinted 2.64 and Clear (calc) 2.79 (floor 2.9).
Measurements (nested session, WhiteSur, 2026-10-19, shader version): shell CPU with 62 Apps icons shown and static, 10 s: default 0.6 percent, dark 0.3, clear 0.2, tinted 0.2; idle with only the Dock: 0.1-0.2 percent in every mode; shell RSS 452-456 MB in every mode. Files grid scrolling (reviewer's measurement, same nested session): default 19.4 and 18.3 percent, Dark 24.9, Clear 23.8, Tinted 22.7 (an effect costs about 5 points while the grid scrolls; accepted). My own virtual-pointer scroll of a 900-item grid showed 0.0-0.1 percent in the Files process in every mode and is not representative. Default mode is identical to main everywhere: the Dock decodes at 2.5x only while an effect mode is active (`TintedIcon.defaultOversample` 2 otherwise). The fallback draws the plain icon at its own size and place (geometry checked in `test_missingShaderDrawsThePlainIcon`). The edge highlight skips low-opacity pixels (a drop shadow is not lit). Reviewer's before numbers (MultiEffect): Apps open-to-first-frame 110-134 ms in effect modes (budget P3 300 ms). `tests/unit/tst_iconmodes.qml` covers mode -> shader index, token ranges, the shader file, tint resolution, the settings keys, the live switch, the visible-only effect and the failed-shader fallback; `tests/shell/desktop_icon_wallpaper.sh` checks that the desktop is styled for the wallpaper.

## Folder colours (owner request 2026-10-19)
Folder icons are recoloured by a step separate from the icon modes: `FolderIcon { source, size, folderColor?, folderGlyph? }` wraps a `TintedIcon` (modes unchanged) and, when a colour applies, draws it through a layer with one `FolderEffect` (`MultiEffect`, colorization 1 over the luminance of the theme's folder; tokens `folderIcon*`). The colour is the folder's own (`folderColor`: `theme`, `accent`, `#rrggbb`, `""` = none) else the global `icons.folderColor` (`Appearance.folderColorSetting`); `theme` means the icon theme's own colour and creates no layer and no effect (`FolderStyle.recolors`). The optional `folderGlyph` is a `Text` over the effect, in a clipped box the size of the icon, at `folderIcon.glyphCenterY` with edge `glyphScale` x the icon: emoji opaque in their own colours, a plain symbol an engraved shade of the folder colour with >= 3:1 against the plate (`FolderStyle.glyphShade`, `glyphMinContrast`; details and measurements in docs/specs/files.md); the symbol rule (one grapheme cluster, no control or bidi characters) is `FolderStyle.normalizeGlyph`, the same as the C++ side. `FolderStyle.js` is pure: validation (`theme|accent|#rrggbb`), precedence, folder icon names, the effect parameters from tokens, the parser of a folder's stored value, of `getfattr` output and of the per-user store (shell side, used by the desktop). The setting is `icons.folderColor` in the contract (schema `pattern`, defaults, `Store.js`, shell store, Files and Settings read it live); Settings > Appearance > Folder colour row (Theme, Accent, eight swatches). The per-folder storage, fallback and Customize Folder are specified in docs/specs/files.md. `tests/unit/tst_foldercolors.qml`.

## Degraded behavior
Compositor without ext-background-effect: surfaces stay tinted but unblurred (fallback via Hyprland layer rules is not implemented yet).

## Automated tests · Manual verification steps
`scripts/dev/test.sh`; nested `scripts/dev/shot.sh` with a striped wallpaper behind the bar at `material.transparency` 1 vs 0.

## Performance · Accessibility · i18n
Each Material with a shadow adds two offscreen layers and a MultiEffect mask; not measured (gate P* not run). Shell RSS after the M1 scenarios: see the S2 report. Legibility gate A2 not measured. Strings live in surfaces via `qsTr()`.

## Known limitations
- All values are estimates, not measured from the reference.
- Blur strength cannot grow with the slider: it is compositor-defined; only the tint changes.
- Light appearance is untested visually. Inter is not installed yet (Noto Sans is used).
- The shadow cut-out mask shows a faint dark artifact at one corner in the light appearance (visible in `cc-light`); not fixed.
- Submenus declare no blur region of their own.
- Qt has no per-glyph font fallback list in QML; the family is chosen once at startup.
