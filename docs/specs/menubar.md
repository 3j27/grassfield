# menubar spec · shell-engineer · M1 (T1/T2 global menus: M3, see menu-bridge.md)

## macOS reference behavior (from design/reference/, described in words — no Apple images committed)
Not yet measured (F1 pending). Assumed: 24 px translucent bar across the top; Grassfield mark (system menu) and bold active-application name (application menu) on the left; status items, Quick Settings icon and clock on the right. Menus open under their title, highlight rows in the accent color, and clicking another title switches menus.

## Purpose and non-goals
Per-screen top bar with the system menu, the application menus (T0: app, File, Window; T1/T2: the application's own menus through grassfield-menu-bridge, `docs/specs/menu-bridge.md`, ADR-0008), status menus and the Quick Settings entry. Non-goals now: Services and Settings… items, Bluetooth/brightness/media items, notification center.

## Functional requirements
0. Material (owner decision 2026-10-18): the bar is transparent by default, like macOS 26/27. Setting `menubar.showBackground` (bool, default false; Settings > Desktop & Dock > Menu Bar, "Show menu bar background") restores the frosted band; text and glyphs then follow the appearance. Insets (`menubar.insetLeft/insetRight`), title padding (`menubar.itemPadding`, 11 per side), status glyph padding (`menubar.statusItemPadding`) and the capsule highlight (23 of 24 px, fully rounded) follow docs/testing/f1-reference-gaps.md.
0a. Adaptive foreground (macOS model, owner decision 2026-10-19): without the background the foreground follows what is behind the bar, per output. `shell/desktop/Wallpaper.qml` reports the relative luminance (WCAG, linear) of the wallpaper strip under the bar to the `BarTone` singleton (`shell/services/BarTone.qml`, pure logic in `BarToneLogic.js`) when the wallpaper or the output changes, never per frame: the procedural artwork is a known gradient (nothing is sampled), an image (the dev override `VisualFixtures.wallpaperFile`, the same path a user wallpaper will take) is drawn onto a small canvas (`menubar.toneSampleColumns` wide, the strip `menubar.toneSampleRows` tall) and averaged. Tone `light` (white text and glyphs, `colorDark.barText`, over a dark wallpaper; also the answer before anything is measured) or `dark` (black, `colorLight.barText`, over a light one). Hysteresis: dark needs a luminance above `menubar.toneDarkAbove` (0.18), light below `menubar.toneLightBelow` (0.175), in between the previous tone stays (first measurement: the middle). The band is as wide as gate A2 allows: white text keeps 4.5:1 up to 0.18 and black text from 0.175. Window content never matters (windows sit below the bar, the bar is over the wallpaper). The tone drives the titles, status glyphs, clock, highlight capsule (white or black hover tint) and the open-title capsule; the shadow is a single faint pass (`menubar.textShadowOpacity`), dark under light text and light under dark text, only while the bar has no background. `qs ipc call bartone status` prints `{output: {tone, luminance}}` (read-only test hook). Gate A2: roles "menu bar text and glyphs, light/dark foreground" (backdrop `bar-light-tone`/`bar-dark-tone`: the wallpaper itself, for the wallpaper colours each tone can be chosen for) in `tests/visual/contrast-roles.json`, exact calculation in `tests/visual/test_contrast_tokens.py`, rendered measure with `tests/visual/contrast.sh --surfaces desktop` (menu bar app name, clock, status icons over white, black, grey, noise, checker: 5.1:1 or more; white/black wallpapers 20:1).
1. One layer-shell window per screen, namespace `grassfield-menubar`, layer Top, exclusive zone 24 px. Keyboard focus always None: hovering the bar or starting the shell never takes the keyboard from the focused window, and while a menu is open its popup holds the keyboard (Exclusive, the overlay). An OnDemand bar used to take the keyboard as a menu closed with the pointer resting on the bar, leaving the window Hyprland still counted active without its keys (`tests/compositor/click_focus.sh`). CTRL+F2 opens the system menu, whose popup takes exclusive keyboard focus.
2. Popups are drawn by `qs.overlay` (one full-screen layer-shell window per screen, mapped only while a popup is open, exclusive keyboard focus, click outside closes, the menu bar strip stays clickable). State: `qs.services` `Popups` (kind, anchor, payload).
3. Grassfield menu: About This Computer (real panel: Omarchy NAME/VERSION_ID from `/etc/os-release`, Grassfield version, kernel, hostname, CPU and threads from `/proc/cpuinfo`, memory from `/proc/meminfo`, graphics from `lspci`; read-only), Settings… (launches `grassfield-settings`; `GRASSFIELD_SETTINGS_CMD` overrides the command in dev), Force Quit… (lists toplevels; the selected app's PID comes from Hyprland window data; `kill -9` only after a second confirmation), Sleep (`systemctl suspend`), Restart…, Shut Down… (confirmation, then `systemctl reboot`/`poweroff`), Lock Screen (PLACEHOLDER, disabled "(coming in M2)"), Log Out <user>… (confirmation, then `hl.dsp.exit()` through the platform layer; Quickshell wraps the request as `hl.dispatch(<request>)` when `Hyprland.usingLua`).
4. Dev guard: with `GRASSFIELD_DEV=1` Sleep, Restart and Shut Down never run `systemctl`; they log a warning and show a notice dialog. Log Out ends only the compositor of the session (the nested one).
5. Application menu (T0, real items only). The bar shows the focused app name (bold) followed by `File` (only when it has real items) and `Window`. The app is identified by foreign-toplevel app id mapped to a desktop entry, never by title. Models are pure (`shell/menubar/model/AppMenuModel.qml`, tested by `tests/unit/tst_appmenumodel.qml`); `AppMenus` (singleton) builds the live context and runs every item through the platform layer. Popup kinds: `app`, `appfile`, `appwindow`.
   - App menu: About <App> (desktop entry name, comment, generic name, id, command; the desktop-entry Version key is not exposed by Quickshell), Hide <App> (moves its windows to `special:hidden`; Dock click or Show All brings them back), Hide Others, Show All (enabled only when something is hidden), Quit <App> (xdg close request for every window of the app; not a kill).
   - File: New Window is shown only when the entry declares a `new-window` desktop action (that action runs), then every other `.desktop` Action as an item. Known limitation: without that action nothing is shown, because launching the entry again is not known to open a new window (`SingleMainWindow=true`, single-instance apps re-activate the existing one) and Quickshell does not expose `SingleMainWindow`. No real item: no File menu.
   - Window: Minimize, Zoom (toggles the maximized state), Enter/Exit Full Screen (toggle through the foreign-toplevel `maximized`/`fullscreen` requests), Move to Desktop > (existing Spaces, the current one checked and disabled, then New Desktop; moves without following), Bring All to Front, then the app's windows (title as plain text, elided to 40 characters, check on the focused one; a minimized window is marked and restored when chosen).
   - Shortcut text comes from one table in `AppMenuModel.qml` that mirrors `config/hypr/grassfield/bindings.lua` (SUPER+H Hide, SUPER+M Minimize, SUPER+ALT+F Zoom, SUPER+CTRL+F Full Screen). Update both together.
   - With a popup open the keyboard focus leaves the app, so the "focused window" of an app is its most recently focused window.
   - T1/T2 (M3): when the shown app exports its menus (Qt/KDE, Chromium; `shell/platform/MenuBridge`), its visible top-level menus follow the app name in its order and open as popup kind `appbridge` (`shell/menubar/BridgeMenu.qml`, routed by the overlay); the T0 File menu gives way (its desktop actions stay in the Dock menu), the T0 app menu and Window stay. Items show the app's labels (plain text), shortcuts, check marks, disabled state and submenus, and choosing one runs the app's own action. Without such a menu the T0 menus stay. Details: `docs/specs/menu-bridge.md` MB11–MB12.
6. Status area, real backends only: Network (Quickshell.Networking: wifi strength icon, wired icon, off icon; menu: Wi-Fi on/off, current network), Volume (Pipewire default sink: icon follows level/mute, scroll ±5 %, menu: volume slider, mute, output device list that selects the default sink), Battery (UPower, hidden when no laptop battery; menu: percentage, time remaining/until full), Quick Settings icon (see controlcenter.md), clock.
7. Keyboard in menus: Up/Down/Home/End, Return/Space activate, Right opens a submenu, Left closes it, Esc closes. Disabled rows are skipped.
8. Every string uses `qsTr()`; every control has `Accessible.name`/role and a visible focus ring.

## Acceptance criteria
- Screenshots of the system menu, app menu, volume menu and About panel (L2). `qmllint.sh` 0 warnings (L0). `tests/unit/tst_menunav.qml`, `tst_popupmenu.qml` (L0).
- Dev guard: Shut Down confirmation in the nested session logs `suppressed systemctl poweroff` and shows the notice (L2).

## Interfaces / contracts (versions)
Reads `Compositor` (toplevels, focused app, pid, hide, close, exitSession), `MenuBridge` (T1/T2 menus, menu/1), `Settings`, `Appearance`, `Audio`, `Connectivity`, `Power`, `Popups`. Test hooks (IpcHandler): `menubar open <system|app|appfile|appwindow|...> <output>`, `menubar panel <about|forcequit> <output>`, `menubar close`, `menubar bridgeState <output>` (JSON: shown window, bridge state, left titles and open bridge menu rows in output coordinates), `controlcenter <transparency|appearance|reduceTransparency|reduceMotion>`.

`windows` IPC (platform, for key bindings): `windows minimize` (focused window), `windows hide` (focused app).

## Dependencies (verified versions)
Quickshell 0.3.1: PanelWindow, WlrLayershell, BackgroundEffect, SystemClock, DesktopEntries, UPower, Pipewire, Networking, Io (Process, FileView), IpcHandler. Hyprland IPC only inside `shell/platform`.

## Degraded behavior
No battery: item hidden. NetworkManager absent: network menu says so. No PipeWire sink: slider shows 0 and does nothing. No `lspci`: graphics line omitted. Unknown PID: Force Quit disabled.

## Automated tests · Manual verification steps
`scripts/dev/test.sh`. Manual: nested-up, open foot, `qs ipc call menubar open system GF-REF`, `shot.sh`; keyboard flows with `wtype -k Down -k Return` on the nested socket.

## Performance · Accessibility · i18n
Event-driven (no polling). Menus have `Accessible.role: PopupMenu`/`MenuItem`. Strings via `qsTr()`. Clock date pattern is translatable.

## Known limitations
- Adaptive foreground: a wallpaper whose strip luminance is 0.16 to 0.19 (for example a mid blue, #1d6fd8 is 0.166) gets about 4.3-4.4:1 whichever tone is chosen (the crossover of white and black text); the faint shadow helps there. One tone per bar: a wallpaper that is light on one side and dark on the other is averaged. The artwork, a colour and the dev image override report one mean luminance; a user picture (ADR-0016) reports its strip statistics and `BarTone.reportStrip` decides from the 5th and 95th percentile: the tone with the better worst-case contrast, with a margin (`menubar.toneMargin`) before it flips, and the frosted band on that output when neither reaches `menubar.toneNeededContrast` (4.5:1) until the wallpaper changes (`qs ipc call bartone status` reports `assist`, `white` and `black`; the shell logs `wallpaper tone=… worst=… assist=…`). The tone switches at the middle of the picture crossfade. Checked in the nested session with generated worst cases (`tests/visual/wallpaper-legibility.sh`: black, white, split, horizon, threshold, blocks, noise).
- Zoom and Full Screen use the foreign-toplevel requests; whether a client or Hyprland honors them was checked only for the menu wiring, not per app. Window menu list with several windows is covered by the unit test, the nested screenshot has one window.
- Move to Desktop lists the Desktops of the focused output only; SingleMainWindow is read per entry once (cached for the session).
- The Sleep/Restart/Shut Down paths were exercised only in the dev guard; the real `systemctl` calls are untested by design.
- Submenus are not blurred (only the top-level panel declares a blur region) and no menu uses one yet.
- About "Version" of an app is unavailable. Menu bar items are not reachable with a global shortcut yet (needs a Hyprland binding calling IPC; config/ is not mine).
- Per-screen focus is global: every bar shows the globally focused app. While a popup holds keyboard focus the bar keeps showing the last app.
- Stages on, Hyprland has no active window (an Exclusive layer holds the keyboard after a swap, stages.md ST24): the bar names the front app of the last `stages` event of the focused output (`front.app`, via `Apps.nameFor`) and shows its T0 menus (macOS: the frontmost app stays named behind a system modal). Display only: the Window menu's Minimize, Zoom, Full Screen and Move to Desktop are disabled (macOS greys window commands with no key window; Hide, Quit, Bring All to Front stay). It ends as soon as Hyprland reports an active window, Stages is off (`on:false`), the plugin is gone, or the front window no longer exists (Hyprland's window list). Never used with Stages off. The app text is treated as untrusted: control and bidi characters dropped, at most 128 characters, drawn as plain text. A popup open keeps the last-app rule above. Pure logic `shell/platform/StagesFront.js`, tests `tests/unit/tst_stagesfront.qml` and `tst_appmenumodel.qml`; the nested check (screenshot of the bar under an Exclusive layer after a swap) is not done yet.
- Wi-Fi network list/connect and Bluetooth are M2 (Quick Settings spec).
